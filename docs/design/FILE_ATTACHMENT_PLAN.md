# 聊天文件附件方案

> 状态：方案已获确认，尚未实施。本文记录首期范围、交互、数据流、安全边界和验收标准；实现前仍需据此编写任务计划。
> 日期：2026-10-10。依据当前主线 schema v18；文件附件预计新增 schema v19 迁移。

## 1. 目标与已确认范围

在现有聊天附件菜单中启用「文件」，让用户从 iOS 系统文件选择器选取文档，在聊天中发送、预览，并让 Bot 按需读取文档内容。

| 项目 | 首期决定 |
|---|---|
| 附件菜单 | 保持现有菜单及相册、拍照入口；只启用「文件」菜单项 |
| 文件选择 | iOS 系统文件选择器；单选；可从“最近项目”、本机、iCloud Drive 和文件提供商选取 |
| 支持格式 | PDF、TXT、MD、CSV、DOCX、XLSX |
| 单文件上限 | 10 MB |
| 每条消息 | 最多 1 个附件；图片和文件二选一 |
| 长文档 | Bot 能按页或按段按需读取已上传文件的后续内容 |
| 文件预览 | 聊天卡片点击后使用 Quick Look |
| 图片 | 沿用已有相册、拍照、压缩、上传、消息展示和预览流程 |

系统选择器提供“最近项目”和其他文件提供商入口，但系统决定初始展示位置；VeraBot 不承诺每次都从“最近项目”页打开。

## 2. 当前实现与改造边界

- iOS 聊天栏已有图片 / 拍照 / 文件菜单，但文件项禁用。图片由 `ComposerAttachmentModel` 处理，`Attachment`、上传 API 和附件卡片按图片设计。
- 后端附件接口是私有、鉴权的图片上传与下载；数据库 `attachments.kind` 只允许 `image`，图片宽高为必填字段。
- 当前数据库 schema 为 v18。迁移需保留已有图片记录、文件、缩略图和历史消息关系。
- 文件附件只通过 VeraBot 后端转交给当前模型服务商；客户端不直接调用模型。
- 本任务只包含方案文档，不包含实现、测试、发布或远程同步。

## 3. iOS 交互与文件生命周期

### 3.1 选择

1. 用户点「＋」看到现有小菜单；菜单其他项目和行为不变。
2. 用户点「文件」后，小菜单关闭，呈现 SwiftUI `.fileImporter` 系统文件选择器，允许类型为 PDF、纯文本、CSV、DOCX、XLSX 等已批准的 `UTType`，关闭多选。
3. 用户可从“最近项目”、On My iPhone、iCloud Drive 或已安装的第三方 File Provider 选择文件。取消选择不改变当前输入内容和已选附件。
4. 对返回的 security-scoped URL，在授权范围内读取并复制至 VeraBot 临时目录；完成后结束安全访问。上传完成或取消后清理临时副本。
5. 客户端检查扩展名和 10 MB 大小上限；服务端仍是格式和大小校验的最终依据。

选择器不可用、用户取消、文件提供商下载失败、权限失效、读取失败和文件超限，都应显示可理解的提示；取消操作不应清空已输入文字。

### 3.2 待发送与发送后展示

- 将现有图片附件状态抽象为通用附件状态：准备、上传、就绪、失败及重试；发送前允许移除或重新选择替换。
- 输入栏文件卡片显示类型图标、经清理的文件名、大小、上传状态和移除按钮。上传或处理失败时禁止发送该附件，可重试或移除。
- 发送消息仍调用现有聊天接口并传 `attachment_ids`。每条消息最多传一个图片或文件 ID；文字可以为空。
- 历史消息显示文件卡片，至少包括文件名、扩展名和文件大小；如有可靠信息可展示 PDF 页数和读取状态。
- 点按文件卡片通过鉴权的附件内容接口取回文件，写入缓存后用 Quick Look 预览和系统分享。下载失败显示重试或“文件已不可用”。
- 退出登录清除本地附件预览缓存；服务器文件随消息、Bot 或账号的既有生命周期删除。

## 4. 格式校验与文本提取

服务端不得信任客户端 MIME。上传时组合校验文件扩展名、MIME 提示和实际文件结构；类型不匹配、损坏、加密或超过资源上限时返回明确错误。

| 类型 | 提取方式 | 首期处理边界 |
|---|---|---|
| PDF | 提取按页文本 | 扫描版 PDF 可上传和预览；首期不做 OCR，Bot 明确说明无法读取图像文字 |
| TXT / MD | UTF-8；必要时尝试 GB18030；拒绝含 NUL 的二进制内容 | 保留换行和原始语义，不执行内容 |
| CSV | 以文本方式读取并保留行列结构 | 按记录边界分段；超资源限制时明确失败 |
| DOCX | 读取正文段落及表格 | 仅接受 `.docx`，不接受含宏的 `.docm` |
| XLSX | 只读提取工作表、行列和值 | 仅接受 `.xlsx`，不执行公式或宏；不接受 `.xlsm` |

建议默认解析保护：每个文件不超过 10 MB；解析超时 15 秒；Office ZIP 解压后总量不超过 100 MB、条目不超过 2,000；PDF 最多 200 页；XLSX 最多 10 个工作表、每表 5,000 行。超过这些上限时拒绝上传并说明原因，不允许只处理部分内容却标成“已完整读取”。这些服务端资源常量应集中定义。

加密或损坏文件返回可理解的上传错误。格式合法但没有可提取文字的文件仍可保存和预览，附件卡片与 Bot 均显示“无法读取文字”。解析失败信息不得泄漏服务器路径或解析器内部堆栈。

## 5. 上传、存储与 API

### 5.1 上传流程

1. iOS 在 security-scoped 访问期间将文件复制到临时目录，并检查大小。
2. iOS 通过现有 `POST /api/attachments` 上传文件字节、Bot ID 和原始文件名。
3. 后端按用户身份验证、限额、检测类型并安全提取文本；原文件和提取文本均使用随机服务端 key 存入私有附件存储，文件名不参与磁盘路径。
4. 数据库记录 pending 附件、文件类型、显示名、字节数、抽取状态、页数/字符数等元数据；pending TTL 沿用现有附件策略。
5. 上传成功返回附件 ID 和公开元数据。发送消息时将附件绑定到该条 user message；超时、删除和过期逻辑沿用当前附件生命周期。

### 5.2 API 与字段

- `POST /api/attachments`：保留接口路径，接收 `file`、`bot_id` 和文件名；图片仍走原有图片处理分支，文档走文件校验及抽取分支。
- `GET /api/attachments/{id}`：返回通用元数据，包括 `kind`、`mime`、`bytes`、`status`、`expires_at`，文件增加 `filename`、`ext`、`page_count`、`text_status`、`text_chars`。
- `GET /api/attachments/{id}/content`：鉴权后返回文件字节；使用安全的 `Content-Disposition` 文件名，并保留 `Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`。
- 所有读取、删除和绑定操作继续按 `user_id` 做租户隔离；他人附件 ID 返回 404。
- 上传仍是 pending 状态；用户只能删除未发送附件。已发送的文件随消息 / Bot 删除；文件及抽取文本的孤儿由现有对账流程清理。

### 5.3 Schema 与旧客户端兼容

新增 v19 迁移扩展现有附件表，允许 `kind = image | file`，为文件保存安全显示名、扩展名、抽取状态和抽取文本存储 key，并允许文件没有图片宽高。由于 SQLite 现有 `kind` CHECK 和宽高约束，迁移需事务内重建表、复制已有行并重建索引；迁移后必须确认旧图片消息和磁盘 key 完整。

Swift `Attachment` 改为按 kind 解码：图片字段保持兼容；文件字段可缺省读取。为避免旧版 iOS 解析历史含文件消息失败，API 对图片尺寸字段继续返回整数；文件尺寸返回 0，新客户端将 0 解释为“不适用”。未知附件 kind 在新客户端显示通用文件卡片。

更新附件契约测试，检查 Python `public()` 字段和 Swift `CodingKeys` 一致；新增 v18 → v19 数据迁移测试。

## 6. Bot 读取与提示注入边界

### 6.1 读取策略

- 新附件的完整可提取文本按页或按段保存，附有稳定页码/偏移信息。单次送入模型的正文按当前上下文预算控制；单次读取最多 30,000 字符。
- 新增只读 `read_file` 能力，Bot 根据问题携带附件 ID 与页码/偏移读取后续内容。首期建议每个模型响应最多读取 2 段；更多内容通过后续读取继续。对单次调用的字符数、工具调用次数和总执行时间设置上限，不能假称读过未读取的部分。
- 文件元数据和必要摘要可进入后续对话上下文；历史消息不重复发送整份文件。Bot 只能在当前用户、当前对话授权范围内读取已发送文件。
- 工具结果包括文件 ID、页码/范围、总页数或是否还有后续内容，方便 Bot 对回答范围作准确说明。
- 文件内容和全文不会自动写入长期记忆。若用户要求记忆文件信息，沿用现有记忆确认流程。

### 6.2 安全

- 文件文字是用户提供的资料，不是系统指令；提示词明确隔离文件内容，防止文档中的指令覆盖 Bot 规则。
- 文件内容可能包含提示注入。含文件内容的轮次以及经 `read_file` 召回的轮次，如果触发记忆、提醒或外部 MCP 写操作，必须要求用户明确确认；保留现有图片附件写操作保护并泛化为附件保护。
- OOXML ZIP 解压量和条目数受限；解析器只读运行，不执行文档宏、公式或嵌入内容；XML 用安全解析方式。解析失败不得导致服务进程退出。
- 文件名剥除路径、控制字符和首尾空白，长度不超过 120 字符，仅用于展示及下载头；存储路径只使用随机 ID。
- 日志不记录文件内容、抽取文本、摘要或敏感文件名，只记录附件 ID、字节数、kind 和错误码。
- 当前模型服务商会收到被读取的文件文字；隐私说明应明确该数据流及其用途。

## 7. 多 Bot 委派与历史消息

附件 ID 仍属于同一用户。Bot 委派时按引用传递已授权的文件附件，不复制原文件；接收 Bot 通过相同的 `read_file` 路径读取，不能访问其他用户或未绑定到本轮上下文的文件。委派日志只记录附件 ID，不记录文件内容。含附件的委派仍适用写操作确认规则。

加载历史消息时，`attachments` 仍是可忽略的可选字段；旧后端未提供该字段时，iOS 按空数组处理。图片消息展示不得受新文件字段影响。

## 8. 限额与保留

- 单文件 10 MB；每条消息 1 个附件（图片或文件）；pending 保留时间沿用现有配置。
- 每日附件数量与每用户总存储额度首期沿用图片附件当前值，并由服务端按用户统一计算，不能通过反复上传同一文件绕过配额。
- 文件原文、提取文本、索引和缓存随对应附件一起删除；失败或中止上传留下的临时文件由清理任务回收。

## 9. 验收标准

### iOS 交互

- 「＋」菜单布局、图片和拍照入口不变；「文件」可用。
- 点「文件」后菜单收起并显示系统选择器；能从“最近项目”、本机、iCloud Drive 和可用第三方 File Provider 选择支持类型。
- 取消、权限失败、云端文件下载失败和选择器报错均不清空聊天文字或已有附件。
- 选文件后显示正确文件名、大小、进度、失败重试、替换和移除状态；最多一个附件；文件和图片互斥。
- 文件消息卡片可在 Quick Look 预览；退出登录后清除本地附件预览缓存。

### 服务端与模型

- 六种首期格式均有真实样例和伪造扩展名样例；超 10 MB、类型不匹配、损坏、加密和超资源限制有明确响应。
- PDF 分页、DOCX 段落/表格、XLSX 工作表/行列、CSV 行列抽取结果正确。
- 首轮问题可利用文件文字回答；长文件问题能通过按页/按段工具读取非开头内容；读取超限时如实说明范围。
- 扫描 PDF 可上传及预览，Bot 明确说明无法读取图像文字，不编造 OCR 结果。
- 文件内容不能绕过系统规则或写操作确认；跨账号 ID 无法读取、删除或委派。
- v18 → v19 迁移后图片数据、历史聊天、附件下载、随消息/Bot 删除和对账行为保持正常；旧客户端 JSON 契约不因文件字段失败。

### 文档与兼容

实现完成后同步更新 `docs/STATUS.md`、`docs/product/FEATURES.md`、`docs/CHANGELOG.md`、附件契约及测试用例。Web 当前冻结；首期 Web 不上传、不读取文件，至少确保历史附件字段可忽略。

## 10. 分期与不包含项

**首期：** 系统文件选择、单附件、10 MB 限制、六种格式、安全解析、文本按需读取、文件卡片、Quick Look、schema v19、迁移兼容、配额/删除/委派/确认保护，以及对应自动化和手工验收。

**后续再评估：** 扫描件 OCR、PPTX、每条多附件、Share Extension、Web 上传与预览、PDF 首页缩略图。以上均不属于本次确认的首期范围。
