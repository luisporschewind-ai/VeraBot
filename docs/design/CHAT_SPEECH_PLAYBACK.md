# 对话朗读生命周期与修复决策

日期：2026-10-11。用户已确认本页行为规则及两个关联问题一并修复。

## 问题与原因

对话页点击朗读后返回 Bot 列表，语音仍持续播放。`VeraBotApp` 持有全局 `SpeechPlayer`，气泡按钮通过环境调用；`ChatView` 退出只收起键盘及取消语音输入，未停止朗读。语音输入取消与朗读停止是两个独立操作。

关联问题：

1. 本机引擎激活 `.playback / .spokenAudio / .duckOthers` 音频会话，但主动停止、自然结束和取消时没有关闭会话，可能持续影响其他音频。
2. 本机引擎的完成与取消回调没有核对朗读对象；旧回调可能在新朗读启动后到达，清掉新任务回调及播放状态。播放器只按消息 ID 校验，也无法区分同一消息的不同播放轮次。

## 已确认的行为

| 场景 | 规则 |
|---|---|
| 返回列表，包括完成侧滑返回 | 停止朗读并清空播放状态；再次进入不自动恢复 |
| 点击正在朗读的同一条消息 | 停止 |
| 点击另一条消息 | 停止上一条，开始新的一条；同时只有一条朗读 |
| 消息因滚动离开屏幕 | 继续；不把消息行的消失作为停止边界 |
| 临时弹层，包括 Bot 详情、相册、文件选择器和相机 | 继续；关闭弹层后仍属于同一对话 |
| App 进入后台或锁屏 | 停止；回到前台不自动恢复 |
| 开始语音输入 | 先停止朗读；权限等待结束后、真正启动麦克风前再次停止 |
| 关闭语音播放设置、退出登录 | 沿用停止行为；账号失效或账号变化也停止 |

只在进入后台时停止；系统权限弹窗导致的短暂 inactive 不作为停止边界。相机全屏覆盖会导致对话页消失，需保留此临时覆盖例外；后台和账号退出仍由根页面执行停止。

## 实现决策

- 保留现有全局播放器，复用既有朗读按钮与引擎，不创建另一套播放器。
- 对话页退出调用 `player.stop()`，全屏相机临时覆盖除外；根页面监听后台、登录失效和账号变化。
- 播放器先使旧轮次失效再停止底层引擎，新回调必须属于当前播放轮次。相同消息再次播放也有新轮次。
- 本机引擎保留当前 `AVSpeechUtterance`，仅当前对象的结束/取消通知可以完成清理。跨线程只保留对象身份，不访问其可变属性；保留引用防止地址重用。
- 停止包含尚未发声但已经入队的朗读。自然结束、主动停止、系统取消均释放本机引擎占用的音频会话，使用 `.notifyOthersOnDeactivation` 恢复其他音频；重复停止幂等。
- 音频会话激活失败时不启动合成并清空播放状态；释放失败时保留占用标记，后续停止可重试。
- 音频会话清理同步完成后才触发结束回调，防止迟到回调关闭录音或新朗读的会话。
