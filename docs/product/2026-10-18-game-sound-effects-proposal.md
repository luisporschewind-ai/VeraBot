# 游戏音效方案：俄罗斯方块与贪吃蛇

日期：2026-10-18；执行状态更新于2026-10-19。下文保留原调研方案；DeepSeek Harness已交付自行合成10个短音、共用播放器、设置与两款游戏绑定并合入main。完整音效计划A1–A3仅部分完成，A4未见真机听测，不再写为音效尚未实施。实际参数/策略与原基线的差异见[核对记录](../tasks/2026-10-19-game-plans-progress-audit.md)；执行入口为[音效计划](../superpowers/plans/2026-10-18-game-audio.md)与[总账](../tasks/2026-10-18-game-upgrade-progress.md)。以下“首选CC0/8–10项”等保留为推荐历史，不覆盖实际自产实现。

## 1. 目标与推荐范围

用户希望先考虑游戏音效怎么做、怎么实现、从哪里找。结合此前“按钮模拟实体按键手感”的要求，建议让短音效、现有震动和按压动画形成一致的操作反馈，并通过少量结果音效增强游戏与陪伴感。

推荐首版采用“柔和机械点击 + 简洁电子提示”，先覆盖俄罗斯方块和贪吃蛇，不加入循环背景音乐。声音短、干净、尾音少；长时间游玩时不刺耳，不掩盖用户正在听的音乐。

素材有三条路径：

- **推荐：现成 CC0 素材筛选与统一处理。** 首版成本和交付范围较可控，但仍要试听、调音量和检查整套风格。
- **自行合成短音。** 按键、提示音可以使用自行编写的振荡器与包络生成，适合统一风格；自然碰撞感需要额外打磨。不能把第三方采样的再合成当作没有来源义务。
- **委托定制一套。** 适合后续建立 Bot 和游戏的声音识别度；需要明确商业使用、修改、随 App 分发等权利。当前不必先走采购流程。

## 2. 声音事件与触发规则

首批建议约 8–10 个基础声音，实际数量在试听后收敛：

- 共用按键：很短的软点击，建议约 30–70ms。用于方向、旋转等普通操作，和已有按下震动同时触发；表示“按下了”，不宣称规则操作一定成功。
- 开始、暂停、继续：共用一组短确认音；只在状态真正改变时发声，不再叠加普通点击音。
- 俄罗斯方块硬降：落定时一个较沉、短促的“咚”；按钮只给按压动画和震动，避免按键声与落地声挤在一起。
- 俄罗斯方块消行：单行轻亮，多行更有层次；首版可用单行、多行两个基础素材，不为每一档分数制作独立旋律。
- 贪吃蛇吃食：短促、圆润的“啵”；跟随实际吃到食物的规则事件。连续转向只有轻点击，不为每格移动发声。
- 失败：温和的碰撞/下降短音；满盘获胜：短庆祝音。结算音建议约 250–600ms，不使用刺耳警报。
- 后续 Bot 接管、交回：各一个柔和短提示，等实际交接成功再播。它们依赖尚未实现的接管机制，不在当前 App 中伪造成功。

普通按键与结果反馈分开处理：同一动作只保留一个主要操作音；硬降后同时消行时，可让较轻的落地声接消行声，或由消行声优先覆盖，试听后决定。自动重力、软降每一格、蛇的每一格移动均保持安静。

按键音建议最短间隔 60–80ms，不能积压后补播。结果音优先于输入音，同时发声数量先限制在 4 路左右，音量和峰值留出叠加余量；这些是待真机验证的初值。

## 3. 陪玩与后台边界

- 前台观看 Bot 代玩时，保留消行、结束等实际结果声，省去 Bot 每次方向与旋转的点击声。
- 接管成功后离开 App 或锁屏，云端继续游戏与手机播放声音是两件事：云端继续，手机停声。再次进入只同步最新局面，不重放离开期间全部音效。
- 重连或重复事件不能重复发声；后续云端事件按会话与事件 ID 去重，状态快照本身不触发历史结果音。
- Bot 的安静模式同时关闭它的主动社交提示音；游戏操作/结果音由独立游戏音效开关控制。首版不自动朗读 Bot 台词。
- 静音时仍以画面、文字和现有触感表达状态，玩法不依赖声音。

## 4. iOS 实现建议

### 播放与资源

两款游戏共用 `GameSoundPlayer`，用 `GameSoundEvent` 表达按键、吃食、落地、消行、结束等事件。游戏规则产生真实结果事件，SwiftUI 操作层产生按压事件；不要在视图重绘或观察整盘分数变化时猜测该播什么，避免恢复状态、重复渲染导致重复播放。

首版先使用有限数量的 `AVAudioPlayer` 实例和可复用播放器池。进入游戏、取得音频会话使用权后加载并准备短素材，不在每次点按钮时读取文件或重新创建播放器。`prepareToPlay()` 会隐式激活音频会话，且播放完成/停止后准备状态需要重新考虑，不能把它当作无副作用的永久缓存。若真机测得首音或连点延迟仍明显，再改为 `AVAudioEngine` + 预解码缓冲区，不提前引入更复杂的音频引擎。

资源建议采用随包分发的短 PCM WAV/CAF，单声道，统一采样率；首批体积目标控制在约 1MB 内，实际以最终素材为准。裁掉头部空白、短淡入淡出、统一主观响度、检查叠加削波；不靠把所有文件峰值拉满来增加手感。离线可用，播放不依赖网络，也不需要麦克风权限。

依据：[Apple AVAudioPlayer.prepareToPlay](https://developer.apple.com/documentation/avfaudio/avaudioplayer/preparetoplay())、[Apple 音频播放与处理](https://developer.apple.com/documentation/avfoundation/audio-playback-recording-and-processing)。

### 与现有朗读、录音协调

当前源码中，TTS 使用 `.playback / .spokenAudio / .duckOthers`，语音输入使用 `.record / .measurement`，两者都管理共享 `AVAudioSession`。游戏播放器不能每次按键都重新设置会话，或在退出时无条件关闭其他功能仍在使用的会话。

建议加入范围很小的会话所有权协调：录音和朗读优先；游戏持有自身有效使用权期间才配置/准备/播放。让出使用权时先停游戏声音；旧页面或迟到回调不能释放新拥有者的会话。朗读或录音占用期间游戏音效静默，释放后仅当前游戏仍在前台才恢复准备。

游戏拥有会话时使用 `.ambient`：遵守 iPhone 静音开关，可以与其他 App 的音乐混合。独立提供“游戏音效”开关并保存选择，游戏内用小扬声器按钮快捷切换；不和“触感反馈”捆绑。首版建议默认开启、整体音量偏低，暂不增加多层音量设置。

暂停时停掉玩法声音，仅允许一次暂停确认；离开页面、后台、锁屏或电话等音频中断时停止所有游戏声音。耳机断开时先停声，不突然把声音外放；不补播中断期间的事件，也不为音效启用后台音频能力。

依据：[Apple ambient](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/ambient)。源码核对位置：`VeraBotTTS/TTS.swift` 与 `Services/Speech/SpeechInput.swift`。

## 5. 素材从哪里找

首选官方 **Kenney**，先找同一套风格，再做少量补充：

- [Interface Sounds](https://kenney.nl/assets/interface-sounds)：官方标注 100 个文件、CC0，适合从按钮与界面点击开始筛选。
- [UI Audio](https://kenney.nl/assets/ui-audio)：官方标注 50 个文件、CC0，可作为开关、确认音候选。
- [Digital Audio](https://kenney.nl/assets/digital-audio)：官方标注 60 个文件、CC0，可试听电子结果音；页面标签偏科幻，不等于整套都适合本产品。

补充来源为 [Freesound](https://freesound.org/help/faq/#licenses)，按 `soft UI click`、`wood button click`、`pop`、`short chime` 等关键词搜索，优先筛 CC0，并逐条检查来源和下载页。该站素材有不同许可，不能把“免费下载”当作整站统一授权；CC BY 需要相应署名，首版不选带 NC 的素材。

CC0 允许复制、修改和商业使用；仍保存每条素材来源、作者、许可版本、原文件哈希与处理记录。许可依据：[Creative Commons CC0](https://creativecommons.org/publicdomain/zero/1.0/)。不提取其他游戏或系统提示音当作素材，不使用来源不明的合集。

筛选流程：每个事件先留 2–3 个候选 → 保存许可与来源 → 裁剪/统一响度 → 做可试听的对照清单 → 选定一套 → 再接入 App。手机扬声器、耳机和连续操作都要试听，单独听悦耳不等于放进游戏合适。

2026-10-19后续入口：保留现有自产素材与播放器接线，补资产记录/校验、共享会话所有权保护、全局调度策略和专项测试，再完成双机试听；不重复从零接入。具体缺项以最新总账为准，Bot接管音仍等真实接管流程实现后加入。
