# 2026-10-10 登录恢复排查

## 原因与修复

demo 和三个测试邮箱均存在于主机当前用户库，密码校验匹配。服务日志显示模拟器及手机的登录请求返回 200，但客户端没有进入首页。

`LoginView.submit()` 与 `sendCode()` 使用 `AppState.isCurrentSession()` 检查异步结果；底层 `AuthSession.isCurrent()` 同时要求会话代号匹配和 `current != nil`。未登录时没有令牌，因此成功结果、错误提示和验证码发送结果均被直接丢弃。

新增 `isCurrentAuthAttempt()` 只核对会话代号，用于登录前的请求；登录后账号数据仍使用原检查。服务器地址匹配和任务取消保护保留，会话切换后拒绝旧结果。

扩大前后端逻辑检查后，另外复现并修复：

- iOS：原账号请求返回 401 时，如果已经换账号，会用新账号令牌重试旧请求；刷新前后增加原会话代号检查。
- 后端：并发 6 次错误密码只记录 1 次，重复注册出现 500，相同刷新令牌可成功消费多次。账号模块使用 `db.tx(immediate=True)`，在读取前开启 `BEGIN IMMEDIATE`；事务内依次检查、更新并提交。其他业务的默认事务方式不变。
- 后端：请求体允许的超长 ASCII / 中文密码超出 bcrypt 72 UTF-8 字节上限时注册返回 500；在邮箱 / 手机号和旧用户名注册中先校验并返回 422。72 字节的 ASCII / 中文密码仍能注册和登录。
