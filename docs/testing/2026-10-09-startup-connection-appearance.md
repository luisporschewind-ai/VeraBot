# iOS 启动、连接、登录与外观专项 — 2026-10-09

## 范围与实现

用户批准本对话四项方案，并明确网络提示直接复用现有 Bot 的状态与表情动作。本次改动均在 iOS 与本地 Kit；不改后端、数据库或 Web。专项变更已提交到本地 main，未推送；头像、外观实验、游乐场以及工程配置的既有工作未纳入专项提交。

- 启动：3 个本地 Bot 错落露面、依次点头打招呼；欢迎层约 1.5 秒，主页面同时准备。减少动态效果使用静态角色并缩短欢迎层；返回前台不重播。
- 登录：Bot 小队 + 留白表单，默认邮箱密码；验证码与手机号方式按需展开，注册与原输入规则保留。可滚动、键盘交互收起。服务器地址从正文移到右上角调试入口。
- 连接：首页加载时显示等待 Bot，成功空列表才显示创建提示；首次请求失败显示全页 Bot 提示，已有列表保留并显示紧凑提示。登录连接失败保留输入，重试原登录 / 验证码操作。
- 动作：断网 / 蜂窝数据不可用 / 漫游限制 / 超时 → `.warning`；服务不可达 / TLS 错误 / HTTP 5xx → `.error`；重试 → `.waiting`。账号错误、验证错误、限流不归类为断网；取消请求不展示错误。
- 调试：登录页、异常页和设置页可进入；包含服务器配置、健康检查、版本、最近连接错误和外观选择。已登录时服务器地址只读；认证过程中禁用调试修改；异步认证响应检查服务器与会话，丢弃迟到响应。
- 主题：使用 `AppearanceWindowSync` 将用户偏好设置到所属 UIWindow；跟随系统恢复 `.unspecified`。不重建 RootView，已输入内容和导航得以保留；Safari 的品牌 tint 随环境外观刷新。

## 主题问题的复现与回归

环境：iPhone 17 / iOS 26，UDID `6FD1E62D-DA65-42B1-81F5-554042006671`。

原生最小探针使用同一 `Theme.swift`、`AppearanceMode.swift`，先在浅色打开 sheet，再将根部偏好切至深色。修复前记录：`window=2 root=2 presented=1`，即根窗口已深色而已打开 sheet 仍浅色；关闭后根窗口维持深色。修复后：`window=2 root=2 presented=2`。

可重复运行：

```sh
frontend/ios/Tools/AppearanceHarness/run.sh <simulator-udid> /tmp/verabot-appearance-harness
```

第三参数 `legacy` 使用旧 `.preferredColorScheme` 路径，用于复现失败。工具在独立的 `com.verabot.appearance-probe` App 内测试，不接触主 App 登录态；退出时恢复模拟器原系统外观。它检查原生 UIWindow、根控制器和当前呈现控制器的实际 trait，同时保存屏幕 PNG。

**结果：16/16**。两种系统外观各执行 8 项：初始浅色、sheet 内切深色、sheet 内切浅色、关闭 sheet 返回、全屏覆盖内切深色、关闭全屏返回、alert 内切浅色、恢复跟随系统。

全量颜色／外观配置扫描覆盖 `Features` 全部 51 个 Swift 文件，以及共用 UI、App 根入口和资源目录；重点路径另做代码审查：页面 / 卡片 / 消息使用主题语义色或系统语义色；剩余白色高光、图片底色、Bot 自身颜色和黑色遮罩属于内容绘制，保留设计。AppLogo 有浅深资源变体。未发现另一处产品页面强制设置 `preferredColorScheme` 或固定 `UIUserInterfaceStyle`。

## 补充：记住账号与密码

- 成功登录／注册后，将最后一次账号、密码及登录方式存入本机钥匙串；验证码登录只记账号，不保存验证码。失败登录不覆盖原有记录。
- 按服务器地址分别保存，登录页首次显示或切换服务器时恢复对应信息；没有记录的服务器清空输入。
- 已有会话令牌仍负责重启后直接进入首页。退出登录清除会话，但保留表单记忆；可在登录页点击「忘记已保存的登录信息」删除当前服务器的记录。
- 密码不写 UserDefaults、日志或文档，钥匙串记录仅本机解锁时可读，不同步到 iCloud。此前没有存储过的密码需要再成功登录一次才能记住。
