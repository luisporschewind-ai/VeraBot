## 实现

- 在原托管工作树 `bot-group-chat-preview/VeraBot-v0.1` 继续，基础提交 `84e0dc3`。未提交、合并、推送，未迁移正式数据库，未调用真实模型。
- 新增群上下文和执行器，复用 `llm.stream_chat`，tools 固定为 None，群调用设置 max_tokens=768；旧私聊请求默认不增加该字段。
- 点名只调用目标成员；讨论按成员顺序进行。后一位会读到前一位已完成的实际回答，仅注入当前 Bot 的人设/指令，不读取私聊、长期记忆或其他成员指令。
- 历史最多 24 条/12000 字符窗口，保留原问题；来源用服务端 member_id 与结构化引用标识，用户正文无法替换结构字段。
- 单成员 60 秒、单轮 240 秒；空完成回复最多再试一次，已有文字后的失败不自动重试。开始和每次调用前检查预算，沿用调用前检查，不做跨群/私聊严格额度预占。
- POST `/api/groups/{id}/chat` 与 `/messages/{message_id}/retry` 返回群 SSE。回复开始前落库，部分文字每 256 字符或有新 delta 且间隔 1 秒保存，最终保存全量。
- 停止先验证所有权并保存标记，再通知当前执行；中止上游并保留部分文字，不调用剩余成员。断线、取消、超时和删除 Bot 竞态均形成可恢复终态。
- Starlette 断线会重复取消 await；只保护上游关闭和收尾事务，不保护模型生成，不创建脱离请求的生成任务。
- 启动将遗留 running/streaming 转为 interrupted，保留文字和原上下文边界；已知 usage 只入账一次，未知 usage 保持 null，无自动续跑。
- 单人重试引用原问题、原轮次结束时的上下文边界，新建 turn/回复，不重复用户问题和其他成员。后来的讨论不会混入原问题重试。
- App「助理」页新增 Bot / 群聊切换和真实创建入口；群列表、创建、分页、点名、讨论、停止、重试、重命名、默认成员、清空/删除接真实 API。失败保留草稿和历史；停止未确认时不显示成已停止。
- 退出页面/后台取消连接并尝试停止，旧会话不得更新状态；本地点名偏好按服务器+账号+群隔离。完成后刷新成员可用状态，历史显示保存的名称/外观，重试回复有标识。
- G0 Debug 预览保留在 Preview* 文件中，仍明确标记模拟数据；正式群聊不依赖示例数据，没有附件、工具或自动朗读入口。
