# MCP M4 OAuth 2.1 implementation plan

> Status: awaiting user review and execution-method selection. No product implementation has started.
> Scope source: approved `docs/design/MCP_CAPABILITY.md` §§5, 15, 18 and MCP-20~24.

## Goal and boundaries

Implement OAuth 2.1 authorization for configured remote MCP plugins, with the backend retaining all token and PKCE secrets and iOS presenting the authorization page through `ASWebAuthenticationSession`. Add Google pre-registration support and the user-facing data sharing notice. Preserve the existing static Bearer connector flow. Do not implement Gmail tools, tool-definition change review, CIMD hosting, multi-worker OAuth state, or arbitrary custom MCP URLs in this milestone.

The Google live flow depends on the owner supplying a Google Cloud project in Testing mode, adding test users, joining Workspace Developer Preview, and providing the iOS OAuth client configuration. Build and contract-test against a local fake authorization server before those prerequisites are available; mark Google live acceptance blocked until then.

## Existing implementation seams

- `backend/verabot/services/mcp/auth.py` currently supports `none` and `static_bearer` only.
- `backend/verabot/db/mcp_store.py` stores encrypted connector credentials; `core/crypto.py` provides the `token` Fernet key. Migration v13 already created `mcp_oauth_clients`.
- `backend/verabot/api/routers/mcp.py` has server management but no OAuth start/callback endpoints.
- iOS plugin detail already shows account, consent, and disconnect controls; networking and app URL callback handling need OAuth additions.
- Existing deployment uses one uvicorn worker, matching the approved in-process callback bridge.

## Implementation tasks

1. **OAuth state and storage contracts**
   - Define one-time OAuth state records bound to user, server, issuer, resource, redirect URI, PKCE verifier, requested scopes, creation time, and optional step-up context; expire after 10 minutes and reject replay or cross-user use.
   - Implement the SDK `TokenStorage` adapter against `mcp_credentials` and `mcp_oauth_clients`; encrypt token, client secret, and registration data with the token key. Keep access tokens in memory where feasible and persist refresh credentials encrypted.
   - Add focused tests for encryption-at-rest, issuer-separated client metadata, credential replacement, expiry, replay, and user binding.

2. **OAuth provider and MCP authorization handling**
   - Bridge the pinned MCP SDK OAuth provider to the app callback using the approved backend-held PKCE flow. Discover PRM and authorization server metadata; use PKCE S256 and `resource`; validate returned `state` and `iss` before code exchange.
   - Support pre-registered clients from environment configuration, while leaving CIMD unavailable and DCR compatibility constrained to the approved legacy fallback.
   - Integrate refresh locking per user/server; map `invalid_grant` to `expired`; handle `403 insufficient_scope` as `needs_scope` and union previously granted and newly required scopes with bounded retries.
   - On removal, call a discovered revocation endpoint when available, then always delete local credentials and the server's related MCP state. Never expose token material in API/SSE/trace/audit/log/error output.

3. **Backend API and lifecycle integration**
   - Add authenticated start, callback, cancel/status endpoints under `/api/mcp/servers/{id}/auth/*`; callbacks bind to the initiating user and return only connected state, safe account label, scopes, and tool count.
   - Route protected requests through OAuth provider and preserve existing unauthenticated/static Bearer behavior. Reauthorize with scope union after a tool reports `insufficient_scope`.
   - Add fake authorization/MCP server contract coverage for MCP-20~24 plus tenant isolation; test server deletion and revocation behavior.

4. **iOS OAuth and consent flow**
   - Add API models and calls for authorization start/callback/status/cancel; add a single `ASWebAuthenticationSession` wrapper that returns callback URL parameters to the backend and handles cancellation/errors.
   - Add registered callback URL handling and display connection progress, account/scopes, expired/needs-scope recovery, and disconnect state in plugin detail.
   - Present the data-sharing notice before connecting and require explicit consent before MCP results can reach DeepSeek; keep the existing per-server consent revoke behavior.
   - Add Kit tests for response compatibility and focused UI/state tests where the project has an established test seam.

5. **Integration, documentation, and acceptance**
   - Run targeted backend OAuth/MCP tests, full MCP/plugin regression, and iOS Kit tests; build the iPhone target. Do not describe a build as manual acceptance.
   - Update MCP design implementation notes, test cases, CHANGELOG, and STATUS with shipped behavior and exact remaining Google/live prerequisites.
   - Provide user-run Xcode acceptance: connect, cancel, successful login, restart persistence, token non-disclosure, expired refresh, insufficient-scope recovery, disconnect/revoke, and consent withdrawal.

## Verification gates

- MCP-20: PRM/AS discovery, PKCE and `resource` in both authorization and token requests, `iss` mismatch rejection, bad/expired/replayed/foreign state rejection.
- MCP-21: database contains ciphertext only; API, SSE, trace, audit, logs and surfaced errors contain no access/refresh token or client secret.
- MCP-22: refresh succeeds under concurrency; `invalid_grant` produces `expired` and a safe `connection_required` event.
- MCP-23: insufficient scope records `needs_scope`; reauthorization requests the scope union and stops after the configured retry cap.
- MCP-24: revoke is attempted when supported; local credential, tools, pending actions, and Bot allow-list entries are removed regardless of remote revoke outcome.
- Existing static Bearer connectors, MCP-10~19, tenant isolation, plugin flows, and iOS decoding remain green.
- Google live E2E is recorded separately from fake-server contract tests and requires the listed Google prerequisites.

## Review focus

- Ensure every callback path consumes state once and cannot complete another user's authorization.
- Confirm auth errors and SDK exceptions cannot serialize response bodies or tokens into logs.
- Confirm a failed remote revoke never retains local credentials and a repeated disconnect is safe.
- Confirm the consent gate applies before MCP output enters model context, including after reconnect.

## Execution recommendation

Use Native execution. The OAuth bridge, API contract, credential lifecycle, and iOS callback are tightly coupled and should be implemented against one shared interface, followed by one independent whole-branch review.
