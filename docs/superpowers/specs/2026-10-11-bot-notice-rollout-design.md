# Bot 提示组件正式接入设计

日期：2026-10-11
状态：待用户审阅
关联基线：`84e0dc3 feat: add Bot notice component lab`

## 目标

将调试实验室中已确认的自有 Bot 提示组件逐步接入正式页面。让短暂、已完成的操作结果获得统一轻提示，同时保留适合停留在页面中的状态、字段错误、空状态、明确确认与系统通知各自的表达方式。

## 用户体验规则

- 每条正式顶部提示都带现有小 Bot，并映射到 `BotAvatarState`；文案简短，操作成功后才发出。
- 顶部横幅只表达短暂结果或下一步明确的操作。持续加载、流式回复、表单校验及需用户留意的可恢复错误继续放在对应内容附近。
- 删除、发送、授权等决定继续使用原有确认流程。系统通知继续由 `NotificationCoordinator` 处理。
- 优先重用业务已有的结果、错误和会话校验；提示层不重复请求、不决定业务成败、不绕过 session generation 检查。
- 以现有柔和实底作为正式接入默认样式。液态玻璃、浅深色和动画仍可在实验室比较，视觉最终偏好由用户在原模拟器上验收。
- 默认不触发额外触感。文案和状态不能泄露技术诊断。

## 页面所有权与数据流

应用主界面持有一个 `BotNoticeCenter`，经 SwiftUI environment 提供给当前页面，并在主页面根视图挂载 `botNoticeHost`。页面仅在操作成功后调用 `show(_:key:replacing:)`；稳定的操作 key 合并重复结果，Center 管理 FIFO 与旧计时器身份。宿主在应用进入后台、用户会话变化或当前界面所有者退出时清空队列。

模态页面有独立可见层级。若某项操作在 sheet 或 full-screen cover 内完成，该 presentation 自己持有 center、注入 environment 并挂载 host，使反馈显示在当前可见层；关闭模态时清空其队列。不同 presentation 不共享待显示队列，也不把提示显示到被遮挡的父页面。

操作按钮的处理闭包由页面宿主提供，`BotNotice` 模型只承载标题、说明、语气、Bot 状态、按钮文字和时长，不承载业务闭包。按钮有明确、可安全重试的对应动作时才显示；没有时提供关闭按钮即可。

## 首批试点

将聊天消息与链接菜单中的复制成功反馈接入横幅。保留原有 `UIPasteboard.general.string` 写入行为；每个复制动作在完成剪贴板写入后显示简短「已复制」提示，使用成功 Bot 状态。当前长按菜单关闭后，横幅显示在聊天页面顶部；重复快速复制不应堆积相同提示。

首批范围限定在 `Core/UI/MessageContentView.swift` 的 `MessageCopyMenu` 及根页面的提示 Center / host / environment wiring。失败处理不另造路径；确认在消息菜单里的复制不引入网络、权限、数据持久化或新的依赖。

## 分阶段扩展

1. **主页面基础接线与复制试点**：建立根页面 Center 的稳定所有权和 environment 注入；接入聊天复制反馈；保持普通页面导航和现有模态行为。
2. **低风险离散操作**：按清单逐页接入已完成的成功结果，例如资料更新、Bot 创建 / 排序、记忆和提醒保存。每种操作只在既有业务结果确认成功后发提示，并按当前页面保留用户可理解的返回位置。
3. **页面状态与模态反馈**：先检查是否需要提示组件。如果现有 Bot 空状态、处理进度和错误文字已清楚，就保持原样；模态中的临时结果在对应模态根部接入独立 Center。只迁移能改善反馈连续性且不会隐藏重要上下文的场景。
4. **全量清单复核与收尾**：逐条复核 174 个候选，记录已接入、明确保留、重复或过时项；更新实验室原有表现、设计文档和项目变更记录。禁止仅凭静态索引把候选位置批量改为横幅。

## 明确排除

- 不把全部 174 项当成应迁移的提示。确认、字段级校验、页面空状态、持续 Bot 状态以及系统推送按其语义保留。
- 不在首批重构 `AppState.missingNotice`。该字段当前至少承载“链接内容已不存在”和“提醒操作因并发修改未生效”两类结果；在有清晰类型与所有者前，不能把不同重要程度的信息共用一个定时横幅。
- 不改变后端 API、认证 / 会话校验、剪贴板权限行为、通知权限、触感设置或业务操作结果。
- 不迁移与提示接入无关的并行语音、群聊或其他工作区改动。

## 接受条件

首批试点满足：

- 普通应用仍按既有流程进入；Settings/Chat 的根页面可访问同一个主页面 Center。
- 复制全文与复制链接均先完成原有剪贴板写入，再显示相同语义的 Bot 横幅；显示横幅不改变剪贴板内容。
- 提示沿用已选默认样式，正常显示、可手动关闭并按时收起；快速连续复制不会产生重复队列噪声。
- 页面离开、应用进入后台或用户会话变化后，旧提示不会在不相关页面继续出现。
- 无关页面、已有错误文字、确认对话框和系统通知行为不改变。
- 用户在原有 iPhone 模拟器上完成复制与返回行为的手动验收后，再扩展下一批。

## 风险与处理

复制菜单可能位于 SwiftUI context menu 等临时系统表面；通知由菜单动作发出，但必须由仍可见的聊天根页面 host 呈现。若目标系统把横幅留在菜单之下，则保持业务写入逻辑不变，将反馈触发下沉到菜单消失后的聊天页面回调，不另建全局 overlay。

根页面 Center 与模态独立 Center 的责任要在接线阶段明确，避免提示被父 host 遮住、重复显示或在离开页面后泄漏。每批只修改一组具体功能，并同步清单，不做自动批量迁移。
