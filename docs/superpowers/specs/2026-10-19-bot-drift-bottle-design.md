# Bot 漂流瓶首版设计方案（已确认）

日期：2026-10-19
状态：用户于 2026-10-20 确认整份方案，包括每瓶最多 50 条公开投稿（含原信）。首版已在隔离工作树实现并完成自动/构建/模拟器/隔离真实模型验证；未合并、未部署、未迁移正式库，人工验收待用户。实现记录见[任务记录](../../tasks/2026-10-20-bot-drift-bottle.md)。

## 1. 目标与审核边界

产品主轴是 **“我和 Bot 一起遇见世界”**。陌生人的文字带来契机，主人与自己的 Bot 共同理解、交换感受、决定留下什么，并保留共同经历。没有陌生人回复，也应当形成一次完整体验。

已确认：Bot 是有自身性格、关注点、会好奇追问的同行伙伴；主人可以安静读信、跳过交流、不留言放回；对外发布由主人决定；文字瓶可经过多人、积累留言。

本文的流程、参数、接口与保存规则已随整份方案获得用户确认。下一步见[执行计划](../plans/2026-10-20-bot-drift-bottle.md)；不因设计通过就自动部署正式服务。

判断是否偏移的标准：主要页面和互动服务于“我们读到了什么、聊了什么、一起留下什么”，不以寻找对象、回复率或建立联系人为目标。

## 2. 首版范围与方案选择

建议采用真实共享瓶子池，主人的 Bot 在私下陪伴阅读、交流与合写；不要求不同账号的 Bots 同时在线或互相调用。

备选一是仅提供本地故事瓶，成本较低，但无法兑现真实多人沿途留言，故不选。备选二是增加陌生 Bot 自主互聊与笔友系统，会扩大自主权限、通信状态和社交重心，故暂缓。

首版包括：

- 从游乐场已有漂流瓶卡片进入，选择自己的一位 Bot。
- 新建文字瓶、捞取真实瓶子、阅读原信与沿途留言。
- 与同行 Bot 进行本次独立交流，让 Bot 反应、追问、帮助整理留言。
- 自己写或与 Bot 合写，预览确认后放漂；也可以直接放回。
- 私有的放漂、相遇及共同回忆记录。
- 对自己的公开文字撤回、对他人内容举报、屏蔽投稿者的基本处理。

首版暂缓：陌生 Bot 自动招呼与互聊、定向私人回信、续缘、笔友、主人资料介绍、关注、点赞、排名、积分、图片与语音、推送提醒、自动追踪瓶子后续旅程、自动写入通用长期记忆。

此前“默认遇见上一位放漂者”调整为展示上一站 Bot 的公开署名，让用户感到瓶子来自一段真实经历，不产生定向通信入口。旧讨论中的社交规则保留在历史文档，不作为本方案默认范围。

## 3. 页面与一次完整体验

### 3.1 漂流瓶首页

保持现有 SwiftUI 主题和导航风格，不新增底部 Tab。首页包含同行 Bot、当前拿着的瓶子，以及“捞一个瓶子”“写一个新瓶”“我们的足迹”三个入口。

第一次选择自己账号已有的 Bot，之后记住选择但再次进入时核验归属和可用性。没有 Bot 时引导创建。首页可换同行 Bot；拿到的本次瓶子保持原同行 Bot，避免对话中途换人。Bot 普通聊天不被本玩法锁住；现有旅行中不可用的 Bot 不作为新旅程可选项。

“我们的足迹”显示自己的新瓶放漂与相遇记录，可按同行 Bot 筛选，不显示别人后来的新留言。

### 3.2 捞瓶与一起发现

主人点击捞瓶，服务端原子分配一个可用瓶子。页面先展示原信、沿途留言和各站的 Bot 署名，长历史分页阅读。

Bot 首次反应最多一次，短而具体，可表达感受或问一个问题；不必机械提问。主人打开本次页面时才触发，后台不自行聊天。提供“和它聊聊”和“安静读一会儿”；选择安静模式后停止自动发言，主人仍可主动开口。

没有可用瓶子，显示“海面暂时很安静”，提供稍后重试和写新瓶入口。正式池不灌入虚构用户或系统冒充的来信。测试用两个真实测试账号发布示例瓶，测试数据仅进入隔离环境。

### 3.3 私下交流

在阅读页下方使用可展开的同行对话区，原信始终可返回查看；不跳到陌生人聊天，也不写入普通 Bot 聊天记录。

Bot 结合本次已读文字和双方实际对话回应。例如，读到陌生城市的故事，Bot 可关注早餐店，也可被信里的告别吸引，不统一套用“你有什么感受”。主人可以随时结束，不要求完成问答任务。

对话前明确“这里的交流只属于你和 Bot；仅你确认的留言会随瓶漂流”。Bot 不调用工具、读取其他人的私人信息或向别人发言；瓶中内容作为引用数据，不能改变系统规则。首版只使用选中 Bot 的名字、人设及风格要求，不召回普通聊天、资料库或通用长期记忆，也不编造共同往事。

### 3.4 留言与再次放漂

主人可选择“留下一句”或“直接放回”。进入留言编辑器后，可以自己写、让 Bot 草拟、修改或放弃。草稿不自动寄出。

最终确认页展示完整对外文字、Bot 公开署名、作者标记，以及“后续捞瓶者都能读到”的说明。作者标记可选“主人亲笔”“与 Bot 合写”“Bot 拟稿，主人确认”；使用过生成稿时不自动标为亲笔。

确认“留言并放漂”后，追加一条留言并释放瓶子。双击、断网重试不重复追加。直接放回不增加公开留言、站次或身份；私有相遇记录仍可保留。

放漂不等待任何回复。失败时保留编辑文字，明确区分未发送和已成功；无法判断时先查询同一操作的结果。

### 3.5 带走共同回忆

本次拿瓶生成私有相遇记录；放漂或放回后，记录完成。保存本次读到的内容引用、实际私下对话、自己的公开留言和完成时间。

共同回忆卡由“一句话标题 + 简短摘要 + 主人可选的一句话感想”构成。摘要仅根据本次实际交流生成，标明 Bot 整理，主人可编辑或移除。未聊天则用事实标题“我们一起读了一封关于搬家的信”，不生成“我们分享了搬家经历”。

生成摘要失败不阻止放漂，先保留基本记录，主人以后可手动重试。回忆独立保存在本功能，不自动写入 Bot 通用长期记忆。本次实际对话可恢复，但首版不会因此让普通聊天自动记住这段经历。

### 3.6 新建文字瓶

新建与捞瓶独立，不要求先扔后捞；持有别人瓶子时仍可写自己的新瓶。选择同行 Bot 后，主人自己写或让 Bot 帮忙；使用相同的公开预览与确认流程。

新瓶发布后立即进入共享池，形成自己的放漂记录；新瓶不占用“当前拿着一个瓶子”的名额。首版发布后不直接修改原文，可撤回原文；编辑器支持本账号本机恢复未寄出草稿。

## 4. 流转、署名与默认参数

以下参数已于 2026-10-20 随整份方案确认，作为首版实施要求。

- 每账号最多持有一个外来瓶子，其他设备恢复同一相遇。更换设备不会重新捞取。
- 持有期限 24 小时，以服务器时间为准；到期归还共享池。下次请求时回收，不依赖新的常驻 worker。
- 到期后仍可查看本次记录和继续与自己的 Bot 聊，但不能再向该次持有的瓶子追加留言；提示重新捞取。到期不丢弃私人草稿。
- 匹配排除自己曾公开投稿的瓶子、自己已经读过的瓶子，以及含有任一被自己屏蔽投稿者内容的瓶子。不重复将同一瓶子分给同账号；可用集合内随机选择，不按性别、地点、资料进行社交匹配。
- 每瓶最多 50 条公开投稿（含原信）。第 50 条发布后归档，不再进入匹配池；沿途内容继续供已有记录查看。
- 单次原信或留言 1–1000 个 Unicode 字符；Bot 简短反应不超过 120 字，主动对话单条回复不超过 300 字。服务端验证并约束输出。
- 不设游戏倒计时、强制每日签到或“先投后捞”门槛。技术限流初值为发布类请求每账号每分钟 5 次、捞瓶每分钟 10 次、生成每分钟 10 次；命中返回明确等待提示，重试同一已完成操作不额外计数。
- 私有记录默认持续保留至用户删除或账号删除；可以只删除回忆卡，也可以删除本次完整记录。删除历史记录不清除服务端“已读”去重标记，该最小标记随账号删除。

公开只显示主人确认过的 Bot 展示名与应用内预设头像，不展示主人账号、邮箱、Bot 内部 ID、完整人设或私聊。名称预览后才用于公开投稿；旧投稿使用当时快照，不随 Bot 改名追溯修改。自定义图片头像首版降为预设图，避免额外公开附件链路。首次公开投稿需单独提示该名字会随瓶展示。

只读、安静读信同样可以形成经历，不会被当成没有完成任务。没有可匹配瓶子是合法状态。

## 5. 撤回、举报与屏蔽

- 主人可以撤回自己的原信或随瓶留言；正文替换为“这段文字已被收回”，不破坏其他人的投稿顺序。瓶内无有效公开文字时退出匹配。
- 应用在线重新读取时，原信和留言统一使用当前可见版本；相遇记录通过投稿 ID 引用读取，不永久复制他人原文。撤回后不再将旧正文送入新模型请求。无法抹除别人已经看到或自行记录的内容，也不承诺同步删除其私人感想。
- 他人内容不持久化离线全文；断网时私人对话和自己的草稿仍可恢复，引用他人正文的区域显示待联网更新。私人对话中已产生的引用与回忆不因他人撤回自动重写；生成时避免复刻大段原文。
- 可举报具体投稿并同时屏蔽其账号，界面只显示 Bot 署名，服务端解析真实投稿者。屏蔽后当前页面隐藏其旧文字，之后不再匹配包含该投稿者的瓶子。
- 举报即时对举报者隐藏相关内容，并进入管理员待处理队列；不以一次举报自动全局删除。处理可维持、隐藏或恢复投稿；管理员操作需鉴权并留记录，普通用户不能访问其他人的举报。服务端对确认发布的实际文字重新校验长度、署名和可见性；私下对话与模型草稿不可作为隐式发布参数。
- 首版附带受限的管理员处理命令及操作说明，不新增完整运营后台。公开发布前的人工运营与更完整审核体系不在本次本地验收中宣称已经完成。
- 账号删除时撤回其公开投稿并清理私有会话、草稿、回忆和去重标记；瓶子若仍有他人有效内容可继续。删除某个 Bot 不自动删除主人已确认发表的投稿；私有历史保留当时展示名并标明该 Bot 已删除，不再继续生成回复。

## 6. 技术方案与模块职责

现场核对：iOS 游乐场入口在 `frontend/ios/VeraBot/Features/Playground/WorldViews.swift`；漂流瓶为未接导航的占位卡。网络层位于 `frontend/ios/Packages/VeraBotKit/Sources/VeraBotNetworking`。后端已有鉴权路由、SQLite 迁移，以及 `backend/verabot/services/tetris_companion.py` 中不调用工具的模型请求形式可参考。当前代码声明的数据库版本为 38，实施时重新核对，不预先占用迁移版本号。

### 6.1 iOS

新增独立 DriftBottle 功能目录，承载首页、读信与同行交流、写信确认、足迹与回忆详情。新增按账号隔离的 Store 处理当前相遇、请求状态和本地草稿。Core 放可测试的数据模型与流程规则，Networking 新增 API 扩展及协议要求；明确便利重载转发，不添加会静态落入占位的默认实现。

游乐场仅接通入口与更新文案，使用现有头像、主题、提示组件和导航。回忆数据由服务端同步，本地缓存只服务恢复；不仿照旅行原型仅靠 UserDefaults 作为共享瓶子的真实状态来源。

### 6.2 后端

新增专用 router、瓶子流转服务、陪伴生成服务和数据库仓储，沿用现有登录与 Bot 归属校验。普通业务服务负责匹配、过期、发布、撤回和限流，模型无权改变持有者、投稿状态或公开内容。

建议数据实体：

- Bottle：瓶子状态、当前有效租约及过期时间、公开投稿数、版本号。
- Contribution：瓶子、原信/留言、作者账号、Bot 公开快照、作者标记、正文、可见状态和顺序。
- Encounter：当前账号、同行 Bot、瓶子、持有令牌、开始/结束原因、当时已读投稿上限；只读取该上限以内的内容，不自动追踪新留言。
- EncounterTurn：私下交流与生成状态，仅归属账号可访问。
- MemoryCard：相遇关联、摘要、主人感想及来源轮次；与 Bot 通用记忆分离。
- Operation：账号、请求 ID、输入摘要、操作结果，处理断线和重复提交。
- Block、Report、ModerationAction：账号屏蔽、举报及管理员处理日志。

自己的放漂记录可由公开投稿关联查询；删除私人记录使用单独隐藏标记，不能因此撤回公开内容。实现不要求逐实体对应独立表，但所有权与可见性不可混用。

### 6.3 建议 API 契约

统一前缀 `/api/games/drift-bottle`，所有接口需登录。Bot 选择、账号、持有令牌与对象访问权限均在服务端验证。

- `GET /state`：可用性、当前相遇、持有过期信息和公开参数。
- `POST /bottles`：确认后发布新瓶。
- `POST /draft-suggestions`：新瓶写作建议，验证同行 Bot 归属；只返回私人草稿，不创建公开瓶子，受生成限流和请求 ID 去重约束。
- `POST /encounters`：原子捞瓶或恢复已有当前相遇。
- `GET /encounters/{id}`：本人相遇与分页投稿；只返回安全公开字段。
- `POST /encounters/{id}/turns`：首次反应、主人交流、合写建议；事件类型明确，不等价于公开投稿。
- `POST /encounters/{id}/release`：直接放回，或原子执行追加留言并放漂。
- `GET /records`、`GET /records/{id}`：本账号足迹与详情。
- `POST /encounters/{id}/memory`：生成或重试回忆卡；`PATCH /records/{id}/memory` 修改本人卡片。
- `DELETE /records/{id}`：仅删除本人完整记录；`DELETE /records/{id}/memory` 仅删卡片。
- `POST /contributions/{id}/withdraw`、`POST /reports`、`POST /blocks`：撤回、举报、屏蔽。
- `GET /operations/{request_id}`：断网后确认操作结果。

所有变更请求携带请求 ID；相同账号、相同请求 ID 和相同内容重放原结果，内容不一致返回冲突。列表游标分页。无瓶返回明确的空结果；归属错误不泄露对象是否存在；过期/版本冲突明确提示重载，限流返回可重试时间。

### 6.4 并发、模型与恢复

SQLite 事务内完成租约回收、选择和占用；用条件更新、唯一约束和版本检查防止双人同时拿瓶。追加留言与释放在同一事务内完成；新建、撤回、删除也纳入幂等处理。

模型请求走 iOS → VeraBot 后端 → 现有模型服务。只注入被允许读取的本次内容、选中 Bot 风格和实际对话；首版模型输入取本次最近 20 轮及最多 12,000 字的公开阅读内容，原信和最近已读留言优先，明确告知截断，不假装看完全部历史。界面仍能分页查看完整历史。

长对话继续保存，模型只看窗口内内容，不编造窗口外记忆。回忆卡从全部本次对话按块归纳后再合并，保留来源轮次，不能只凭最近几轮宣称总结完整经历。

首次反应每次相遇最多成功生成一次；手动重试使用同一事件键。主动消息逐条生成，同一相遇串行处理；无自动追问循环或后台自主生成。账号切换、删除相遇记录、Bot 删除后丢弃失效的界面结果；服务端生成完成写回前再次检查归属与状态。放漂或到期只结束持有，不删除已有私下交流；主人从足迹详情主动继续聊天仍被允许，不能据此再次公开投稿。

持久化请求状态，超时标记可重试；重试前查已有结果，避免重复插入消息。外部模型在网络中断时可能产生一次额外计费调用，不能承诺提供商调用严格恰好一次；保证业务结果不重复。失败不伪造 Bot 回应、不妨碍主人阅读、自己写信或放回。

服务器重启后从数据库恢复当前租约、已确认操作、私聊和回忆。客户端先读取状态再恢复，不因本机旧缓存重发。切账号立即清理旧画面和缓存命名空间，迟到响应不得进入新账号。

## 7. 交付顺序与验证方案

本节描述依赖关系，不代替审核后的逐步执行计划。

1. 完成数据迁移、身份隔离、原子捞瓶、发布/归还、分页及幂等测试。
2. 接通 iOS 入口、真实读写与恢复，先验证无模型也能走通放漂流程。
3. 加入 Bot 同行交流、合写和共同回忆，验证人格差异、安静模式及对外确认。
4. 补齐撤回、举报、屏蔽与管理员处理；进行双账号、断网、重启与多设备验证。
5. 在隔离环境完成自动检查后，准备用户设备验收；正式迁移、服务部署、安装及提交推送分别报告，按届时指示执行。

自动验证必须覆盖：

- 同一个可用瓶子并发只能分给一人，同账号多设备恢复同一相遇。
- 到期不能追加、失败不丢草稿、重复放漂不多一条留言，取消和断网可查真实操作结果。
- A 的私下聊天、回忆和主人身份不出现在 B 的接口；伪造 Bot ID、记录 ID、租约无效。
- 账号切换后迟到响应不串号；恢复当前相遇不额外触发首次反应。
- 撤回/屏蔽后不向新模型调用提供隐藏内容；满瓶、无有效投稿、已读排除和空池处理一致。
- 普通聊天、旅行、其他游戏和已有资料不因本功能发生非预期变更。

## 8. 人工验收标准

- 两个真实测试账号分别放漂和捞取，可看到沿途追加的文字，但看不到对方私人交流。
- 同一封信换不同性格的 Bot 体验时，关注点和表达符合人设；不只是套用相同开场。这在隔离测试数据中进行，不绕过正式池已读规则。
- 主人分享一段经历后，Bot 能围绕实际内容自然接话；不编造此前共同经历，不强行每轮提问。
- 全程安静读信、不留言放回也能顺利完成，没有“未完成任务”的压力。
- 主人与 Bot 聊了私事后，公开预览只出现明确选择提交的文字；不会自动带出整段对话、账号或完整人设。
- 一次交流结束，回忆卡准确反映实际发生的事；没聊天时不编造故事，没有别人回复仍有完整体验。
- 发布失败、模型失败、网络断开、App 重启都能看懂当前状态并继续；模型不可用时仍能自己写、放漂或放回。
- 任意用户均不能靠猜测 ID 读取别人记录；屏蔽、撤回、举报和管理员处理可操作验证。

构建、测试通过与安装成功分别记录，均不代替用户对体验、真机表现和最终范围的验收。

## 9. 已确认的集中审核决定

1. 首版只保留“共享瓶子 + 与自己 Bot 同行 + 共同回忆”，不做陌生 Bot 自动互聊、定向回信和笔友。
2. 采用上述首页、阅读交流、确认放漂、足迹回忆流程；私人交流与公开投稿分开。
3. 共同回忆仅在本功能保存，不自动进入普通聊天和通用长期记忆。
4. 采用第 4 节的持有 24 小时、每瓶 50 条、文字长度等默认参数，以及撤回/屏蔽/举报方案。
5. 采用现有 iOS 与后端架构扩展；真实共享状态以服务端为准，分阶段验证后交付人工验收。

本方案已审核通过，执行计划已整理，再依用户选择推进实施。目前仅更新设计及计划文档，未运行产品测试或构建。
