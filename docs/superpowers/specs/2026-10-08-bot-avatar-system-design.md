# Vera Bot 新版形象体系设计

日期：2026-10-08。状态：根据用户已确认的六点要求形成的书面设计，待审核；尚未实施。

## 目标与用户确认

在新版头像实验室内扩展机器人，让它成为共享动画体系中的第一个参数化模板。
增加六种手动工作状态，使眼睛、头部、天线共同表达同一个状态；新增版本化外观保存。
用户稍后提供其他角色的指定形状，本次不自行设计额外角色。

1. 原有 17 种状态的天线闪动保持原版规则，不改为呼吸或渐隐。
2. 新增思考、召回记忆、执行工具、委派、回复、等待确认；不接执行状态机或聊天事件。
3. 使用共享动画体系＋参数化模板；第一版只有现有机器人模板。
4. 天线表达和形象状态绑定，不提供独立心情或独立天线状态选择。
5. 新增带版本的外观配置，兼容已有 avatar / color / 照片。
6. 实验室提供对应的状态、模板外观、保存与验证入口。

## 当前代码依据

- `RobotAvatarLabView.swift`：17 状态、尺寸、颜色、圆角、全状态演示；外观只保存在页面内。
- `RobotAvatarMotion.swift`：表情帧包含眼睛、头部和 antennaOpacity。
- `RobotAvatarView.swift`：统一时钟与独立天线弹簧，Canvas 绘制和手势。
- `RobotAvatarInteraction.swift`：拖拽 / 挤压覆盖动作；当前结束后仍保留 overridesAction。
- `BotAvatarFigure.swift`：旧形象短 ID 存入 avatar；正式形象映射与本次实验分离。
- `backend/verabot/api/schemas.py`：avatar 最长 8 字符，color 最长 9 字符。
- 后端当前代码的迁移版本为 14，新增外观列计划使用 v015；实施前再次核对版本。

## 一、状态与天线共同生成

原 17 个动作的顺序、几何与时间曲线保持现有复刻版本，新增六个工作状态排在其后。
统一状态列表共有 23 项。工作状态持续循环，直到手动换状态或停止页面动画。

使用一个状态描述定义标题、是否持续、循环时长、演示观察时长、运动参数和天线规则。
同一次采样输出眼睛、头部、天线亮灭和天线姿态偏移，天线弹簧仍只负责跟随与回弹。
天线不单独启动计时器，也不从状态之外推断情绪。

下表是六种新状态的第一版设计值；每项进入时用 200ms 从当前姿态过渡。
循环时间从进入过渡完成后开始。眼睛位移使用现有 240 单位坐标，默认眼位 ±34 / y=6。

| 状态 / 标识 | 循环时长 | 眼睛与头部 | 天线联动 |
| --- | --- | --- | --- |
| 思考 / thinking | 2400ms | 双眼向左上缓移，轻眯，再回中；头部轻倾 ≤2° | 同步向上偏移最多 2 单位；1200ms 亮灭周期 |
| 召回记忆 / recalling | 2800ms | 视线先左上、再右上、回中，幅度小于发呆；头部跟随 | 随头部左右倾，1400ms 亮灭周期 |
| 执行工具 / working | 1800ms | 双眼略收窄，按两个节拍交替微动；头部小幅下点 | 按相同节拍上下偏移 ≤3 单位，900ms 亮灭周期 |
| 委派 / delegating | 2400ms | 向右观察、轻点头、回中，表示交接 | 向右偏移 ≤4 单位后回正，1200ms 亮灭周期 |
| 回复 / replying | 1200ms | 双眼有轻微宽高变化，头部微点；与用户输入光标明显区分 | 同步小幅上弹 ≤2 单位，1200ms 亮灭周期 |
| 等待确认 / awaiting-confirmation | 2400ms | 保持面向用户，眼睛稍睁大；末段一次很轻的点头 | 保持朝上，在每个循环末段熄灭 480ms，提示等待回应 |

新状态的亮灭沿用原版 80% 可见、20% 不可见的硬切换方式。
运动曲线使用现有 smooth / cubic 等函数，循环起止的位置及速度连续。
新增表现是 Vera 自定义状态，不称为原版 Demo 已有动作。
系统减弱动态效果时输出代表性静态表情，天线始终可见，无闪动和弹跳。

### 原版天线规则

参考固定版本：Agent Robot Avatar 0.5.2 / b8b3fd497a1d103ff6f028d21769805cb76c1068。

| 状态 | 周期 | 可见 / 不可见 |
| --- | --- | --- |
| 输入 | 1200ms | 960 / 240ms |
| 发送、警告 | 1000ms | 800 / 200ms |
| 成功 | 1100ms | 880 / 220ms |
| 内容阻止 | 900ms | 720 / 180ms |
| 系统错误、惊讶 | 800ms | 640 / 160ms |
| 其余十种原状态 | 不闪动 | 始终可见 |

原有单次动作结束后天线恢复可见；输入持续闪动至切换。
交互阶段允许沿用现有常亮反馈。释放及短暂反馈结束后，恢复正在播放的状态；
持续状态继续自己的时间线，单次动作若已结束则保持其正常终态，睡眠保持闭眼。
本次不改变“原版熄灭期间不命中独立天线”的行为，避免扩大交互改动范围。
自然眨眼与视线游移开关不再重置动作或天线计时；进入后台 / 离屏仍停止任务。

## 二、共享动画与模板

配置 → 模板解析 → 同一状态帧采样 → 模板几何 / 眼位映射 → SwiftUI Canvas 绘制。

模板负责静态几何，状态描述负责运动语义，交互层负责局部形变和临时反馈。
现有机器人调用入口保留适配，避免复制另一套动作时间曲线。

第一版登记一个模板：`cx-robot`，沿用原轮廓、默认圆角 0.5、两只眼睛和独立天线。
保留来源与 MIT 声明，不声明为 Vera 原创角色。

模板定义至少包括：

- 稳定 template_id 与几何版本。
- 归一化轮廓生成器及有限的形态参数。
- 左右眼锚点、可见区域与表情缩放范围。
- 附件锚点、默认半径、运动范围与绘制溢出范围。
- 支持天线、双心、局部挤压等能力及对应的替代表现。

当前配置只开放 roundness ∈ [0,1]，其他角色参数随用户指定形状扩展。
未来无天线的模板通过自己的附件或头部运动表达同一状态，不画悬空的机器人天线。
不同角色的轮廓不强制直接插值；选择模板时短暂过渡，模板内部才做兼容路径形变。
第一版不提供形状编辑器、随机生成角色、独立情绪混合或云端角色资源下载。

## 三、版本化外观配置

新增 `appearance` 字段，和旧 avatar / color 并存。示例：

```json
{
  "schema_version": 1,
  "template_id": "cx-robot",
  "template_version": 1,
  "palette": {
    "body": { "space": "display-p3", "red": 0.917647, "green": 0.25098, "blue": 0.270588 },
    "eyes": { "space": "srgb", "red": 0.972549, "green": 0.972549, "blue": 0.964706 }
  },
  "parameters": { "roundness": 0.5 }
}
```

颜色保存色域和数值，避免把截图的 Display P3 分量错误解释成 sRGB。
三个旧快捷配色和截图的 11 色选色卡保留，选择后生成同一种配置格式。
机器人天线使用 body 色；状态不改变角色主色。
不保存当前动作、工作状态、演示进度、拖拽坐标或 transient 心情。

### 后端

- SQLite bots 新增可空 TEXT 列 appearance，保存规范化 JSON；旧行默认 NULL，不回填头像。
- 幂等迁移登记进现有迁移链；测试只使用临时数据库，不启动正式数据库升级。
- POST /api/bots、GET /api/bots/{id}、GET /api/bots、PATCH /api/bots/{id} 支持 appearance。
- PATCH 缺省 appearance = 不修改；明确 null = 清除新版外观；对象 = 整体替换。
- appearance 字段单独验证和序列化；保留用户隔离及现有保存事务。
- schema_version、template_version 为正整数且拒绝布尔值；第一版写入仅支持 schema_version=1。
- template_id 匹配 `[a-z][a-z0-9-]{0,63}`；允许未安装模板 ID，供跨端保存和后续模板扩展。
- 颜色空间限 srgb / display-p3，分量是有限数值且 ∈ [0,1]，布尔值无效。
- parameters 第一版只允许 roundness；拒绝多余字段、越界值，避免保存任意动画脚本或路径。
- 整个配置编码后最多 4096 UTF-8 字节；非法写入返回 422。
- 仅提交 appearance 时，旧 avatar、color、照片、权限和其他资料均不修改。

### Swift 与兼容

VeraBotCore 定义可编码外观文档和颜色模型；UI 层再转为 SwiftUI Color。
Bot、BotCreate、BotPatch 增加外观字段，PATCH 必须区分不修改 / 清除 / 替换。
保留未知版本或未知模板的原始 JSON，Bot 解码不因此失败；实验室显示无法预览的说明，
用户没有明确重新选模板时不覆盖该配置。
旧服务端响应缺少 appearance 时，普通 Bot 功能照常；保存新版外观时必须核对响应中的配置，
服务端未回传或不一致则提示保存未成功，不能把旧后端忽略新字段误报为成功。

外观保存到 Bot 后，本阶段仅供实验室读取和预览。
正式列表、聊天头像、照片优先规则及旧角色映射仍走现有路径；正式切换另行安排。
Web 本次不改界面，接口字段为之后跨端共享提供基础。

## 四、实验室入口与流程

调试页顺序仍为“头像实验室”→“新版头像实验室”。新版页面提供三个清晰入口：

1. **状态演示**：原 17 状态与新增 6 状态分组；主预览显示当前名称。
2. **形象与配色**：现有机器人模板、三个快捷配色、11 色选色卡、圆角和尺寸。
3. **外观配置**：保存到本机实验室、读取 / 保存到指定 Bot、恢复实验室默认配置。

状态演示增加“演示全部 23 种”“循环当前”“状态切换测试”。
全状态演示按列表顺序播放；原动作沿用动作时长＋800ms，新增持续状态各观察 4800ms。
结束回正常，显示项数进度；手动选择、停止、离屏或退后台取消演示。
循环当前按动作描述处理：持续状态不断续播，单次动作完成和回正后重播；停止后保留当前表情。
状态切换测试固定播放“思考 → 执行工具 → 委派 → 回复 → 等待确认 → 成功 → 正常”，
只驱动本页预览；每项可观察至少一个循环或完整单次动作。

外观编辑使用草稿：调整即时预览，点击保存才持久化。
本机实验室配置单独存储，不写 Bot；成功保存后下次打开恢复外观，状态回到正常。
保存到 Bot 先选择本账号 Bot，再点击“保存新版外观”；请求只 PATCH appearance，
页面标明“仅保存新版外观，正式头像暂未切换”。失败保留草稿并可重试。
读取 Bot 配置只更新实验室草稿，不发送请求修改资料。
本机恢复默认与清除 Bot 已保存外观为不同操作；清除远端必须选择 Bot 并明确点击清除。

## 五、交付与验收

实施可拆成三个可验证单元：

1. 共享模板与状态：机器人外观不漂移；新增六种循环；状态与天线共用描述和时钟。
2. 保存契约：后端迁移 / API、Swift 编解码及旧数据兼容；不切换正式头像。
3. 实验室入口：预览、全状态与循环、外观草稿、本机保存、指定 Bot 配置读写。

必须验证：

- 原 17 状态闪动周期、80% 占空比、完成后恢复，与固定上游版本相符。
- 新 6 状态无限循环采样的几何有限、周期边界连续，天线同步且始终在绘制范围。
- 拖拽 / 挤压反馈结束恢复当前状态；自然动态开关不重置动作与天线时钟。
- 23 状态均可选、可重播、可演示；长动作不中断，停止与快速切换不残留旧任务。
- 四种尺寸、配色、圆角、减弱动态效果、离屏与后台行为。
- 外观配置 P3 / sRGB 编解码往返；缺字段、未来版本、未知模板安全读取。
- 临时数据库旧版迁移、重复迁移、POST/GET/PATCH/clear、无关 PATCH 不清空外观、跨账号隔离。
- 旧服务端忽略 appearance 时不会显示保存成功；网络失败不丢草稿。
- 本机重进恢复外观；读取 / 保存 Bot 配置时旧头像、照片和权限不改变。
- Swift 包测试、后端相关测试、iPhone 17 / iOS 26 构建与实验室真实操作验收。

本次不提交、合并、推送或发布；保留已有 project.pbxproj、InfoPlist.xcstrings 和其他本地改动。
不运行正式数据迁移，不接聊天状态机，不提前创建用户尚未提供的角色形状。
