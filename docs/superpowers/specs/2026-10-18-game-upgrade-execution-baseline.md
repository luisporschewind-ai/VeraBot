## 3. 掌机操作区（已确认）

以 [v2 设计图](../../product/2026-10-18-tetris-controls-visual-proposal.md)为准：左十字键左右移动/向下缓降，上方向不绑定；右上 A 顺时针旋转，左下 B 直接落下；START 暂停/继续，SELECT 打开游戏菜单；重开在菜单内，进行中先暂停并确认。菜单另提供玩法、触感设置入口，音效完成后再显示音效开关；不出现未实现的接管按钮。

实施初值：十字键整体 132×132pt，三个有效方向每个命中区至少 44×44pt；中心、上臂不派发动作。A 可见直径 64pt、B 56pt，独立命中区之间至少 12pt；START/SELECT 可见键帽约 34×14pt，但命中区至少 44×44pt且互不重叠。尺寸为排版初值，可适配小屏，不改变已确认相对布局。

左右/缓降按下立即操作一次，180ms 后开始重复，每 70ms 一次；A/B 每次完整点击只派发一次，不长按连发。A/B 沿用原生 Button 的释放/取消语义，震动仍在按下沿一次。取消、滑出、暂停、开菜单/聊天、结束、切伙伴、后台、离页、重开均清空输入。左右同时按下以最后按下者为准，释放它后不自动恢复旧方向，须重新按下；不缓存跨暂停或跨局动作。

SELECT 打开菜单先暂停，关闭菜单保持暂停；START 在暂停后发起 3/2/1 倒数，倒数可取消，结束后才恢复输入。已有“聊聊”、伙伴选择、安静模式、失败重试均保持可达。掌机布局 L2 可先沿用原规则；倒数属于 L2 的页面行为，不要求重写规则。

完整 20 行、下个方块、右侧 Bot 和操作区同屏可见，暂停/气泡不改变棋盘尺寸。保留现有主题和照片头像；不以生成图替换真实角色。游戏数据行紧凑化，正文说明进玩法菜单。

## 4. 本地引擎与规则默认值（L1 保留原行为，L3 才启用下列升级）

位置为列向右、行向下；棋盘 10×20。清行得分保持 100/300/500/800，缓降每成功移动一格 +1，硬降每格 +2；重力间隔 `max(130,620-(lines/10)*55)` ms。

新增引擎接口：`TetrisGame(seed: UInt32)`、`init(restoring: TetrisState) throws`、只读 `state`、`ghostCells`；`apply(_ action: TetrisAction) -> [TetrisEvent]`、`advance(milliseconds: Int) -> [TetrisEvent]` 为 mutating。动作：start/pause/resume/moveLeft/moveRight/softDrop/rotateClockwise/hardDrop；重开用新实例。事件：moved/rotated/locked/linesCleared(count)/spawned/paused/resumed/ended，均含单局单调 eventSequence。L1 的 state 使用 `legacy-1`，只提取现有规则；L3 升级为 `vera-tetris-2`，仅该版本允许上传接管。

`vera-tetris-2` 固定约定：

- 初始 ready，点 START 开始；暂停保存精确剩余计时，恢复倒数不计入逻辑时间。
- 固定 10ms 逻辑步；非负 elapsed 保留不足 10ms 的余数，不可把一次 advance 调用次数当速度。每步按输入 → 重力 → 落地计时 → 消行计时的顺序处理；暂停/ready/over 不推进。
- 七种方块按 I/J/L/O/S/T/Z 编码 1…7，空格 0。每袋各一种，Fisher–Yates 洗牌；PRNG 为 UInt32 xorshift32（依次 xor 左移13、右移17、左移5，每步掩码32位），零种子替换为 `0x6D2B79F5`。取 `[0,n)` 用 `x < 2^32-(2^32 mod n)` 的拒绝采样再取余，避免 Swift/Python 随机 API 差异；保存完整 rngState、剩余 bag 和公开 next。
- J/L/S/T/Z 采用 3×3 旋转中心 (1,1)，初始四格依次为 J:(0,0)(0,1)(1,1)(2,1)，L:(2,0)(0,1)(1,1)(2,1)，S:(1,0)(2,0)(0,1)(1,1)，T:(1,0)(0,1)(1,1)(2,1)，Z:(0,0)(1,0)(1,1)(2,1)。顺时针变换 `(x,y)→(2-y,x)`。
- I 初始 (0,1)(1,1)(2,1)(3,1)，中心 (1.5,1.5)，顺时针 `(x,y)→(3-y,x)`；O 固定 (1,0)(2,0)(1,1)(2,1)，旋转不改变坐标且不刷新落地计时。出生偏移 x=3,y=0。
- 自定义顺时针碰撞试移顺序固定为 (0,0),(-1,0),(1,0),(-2,0),(2,0),(0,-1),(-1,-1),(1,-1),(0,-2)；首个合法位置成功，全部阻挡则不动。不宣称采用标准 SRS。允许顶部负行的活动格，锁定时任一格在顶部外即结束且不部分写盘；出生阻挡结束。
- 触地缓冲 500ms；成功左右/旋转最多刷新15次，每块落定后重置次数。离地时不倒数落地计时，重新触地仍沿用该块次数；失败动作与 O 旋转不刷新。缓降触地不立即锁定，硬降立即锁定。
- 锁定后先算满行，消行动画180ms内冻结玩法输入；一次性移除满行、加分、发 linesCleared，再生成下一块。无满行直接生成。暂停可以中断动画并保存剩余时间。ghostCells 与硬降使用同一碰撞计算。
- 新局清空时钟、输入、事件序号、旧请求；不接续 legacy-1 局面，不把旧版本局面直接上传为新规则。

### 可恢复状态（C1 需据此提供 JSON Schema 与固定样本）

`TetrisState` 包含 ruleVersion、board（200个0…7，逐行）、active（kind/rotation/x/y，可空）、next、bag、rngState、score、lines、lockedPieces、phase、resumePhase、logicalTimeMs、stepRemainderMs、gravityRemainingMs、lockRemainingMs、lockResetCount、clearRemainingMs、pendingClearRows、eventSequence、endReason。phase 为 ready/running/clearing/paused/over，resumePhase 仅允许 running/clearing。所有计时为整数毫秒，logicTime 不因服务停机追赶；校验范围、四格互异、重叠/越界、phase与计时一致性。

## 5. 陪玩默认值

不改变现有人设、账号隔离、模型调用路径或仅本局对话边界。主动每局至多3次、失败也计数、间隔至少30秒；非终局自动发言最多2次，为结束预留1次。终局遇冷却不抢发，显示“本局回顾”主动入口；手动请求不占主动额度。以可注入单调时间测冷却，换伙伴不补次数，重开才重置。

事件本地反应：单行 smile 1.2s，多行 success 2s；堆叠最高≥15进入 warning 1.2s，降到≤12才解除危险状态，重复事件不连续警报；暂停/聊天 idle（倾听状态文案），结束 failure 1.5s后idle，不责备。延迟任务按单局/伙伴/会话代次隔离。气泡自动显示5s后收起，聊天面板保留完整文本；安静模式关闭主动文字，保留低强度本地表现。

自动发言后端上限由60收敛到24个字符，聊天仍180；界面2–3行，完整内容进暂停面板，不把预设台词冒充模型输出。摘要可增加事实，不输出未经引擎验证的具体列位建议。

## 6. 音效默认值

首批8项：keyPress、stateConfirm、hardDrop、clearSingle、clearMulti、snakeEat、gameEnd、gameWin。Bot handoff/return音等 C4 真实交接完成后再加入；不伪造接管事件。

候选先从原音效方案列出的 Kenney CC0 包挑，每项2–3条候选并归档来源/许可。最终48kHz、16bit、单声道 PCM WAV；总目标≤1MiB。按键30–70ms、普通结果≤250ms、结算250–600ms，头部静音≤5ms，短淡入淡出，无削波；最终主观响度以真机试听确认。素材未选定不阻止完成“候选包”任务，但阻止声称“最终音效已接入”。

独立开关 `SettingsKeys.gameSoundEnabled = vb_game_sound_enabled`，默认 true，初始播放增益0.35；现有触感开关独立。按键音最小间隔80ms、不排队，最多4路，优先级终局3、消行/吃食2、状态1、按键0；满路时淘汰最老的最低优先级，低优先级不得打断高优先级。硬降后清行由消行声覆盖尚未结束的硬降声，不叠成过响一击。

录音优先级3、TTS2、游戏1；共享会话通过租约代次协调，旧释放不关闭新拥有者，停声先于让出会话。游戏拥有时才设 ambient并预热；暂停停止玩法声，可播一次状态确认；后台/离页/锁屏/音频中断/耳机断开立即停止和释放。耳机断开后保持游戏音效关闭到用户再次显式开启，不自动外放；不为音效添加后台音频权限。重连不补播历史事件。

## 7. 云端接管默认值

仅俄罗斯方块、同一局、单账号同时一局 Bot 托管。稳健规划器负责合法动作，模型仅可选表达，不参与逐帧循环。用户明确交出才托管，托管不自动重开；原设备收回，其他设备只读。第一版服务端规则版本固定 `vera-tetris-2`，不接受旧版或不同规则。

API `/api/games/tetris/sessions`：POST交接创建；GET按session_id读取；GET `/operations/{request_id}` 查询结果；POST `/{id}/commands` 执行 pauseBot/resumeBot/reclaim/end/changeBot。每次写入带 requestID(UUID)、clientID(UUID)、expectedVersion(Int64)、expectedEpoch(Int64)，交出额外带 botID、完整snapshot。后续再次交出同一局使用 command handoff + 新snapshot，不能创建第二条会话。响应含 id/version/controlEpoch/controller/runState/latestSnapshot、实际玩家/Bot分段统计，不暴露私有规划器输入或未公开出块序列给模型。

首次创建expectedVersion/expectedEpoch均为0，成功初始化为1；后续以最后读取的服务端值比较。操作查询完整路径为 `/api/games/tetris/sessions/operations/{request_id}`。运行中会话按控制段保存起止score/lines与增量；手动段再次交出时从上次交回基线计算实际增量，首次从0计。清行分数/行数归锁定该块的控制方；交出发生在玩家clearing时，服务端session另存`pendingClearController=player`，待清行事件原子结算再清空，不能算成Bot贡献。两类累计与总成绩相加一致，事件唯一键防止重复计入。

controller 只有 player/bot；runState 为 paused/running/over；交接中是客户端 pending 状态，不是第三个控制方。查询 requestID 不会触发重做。成功写入幂等；同request不同payload报409，不存在/非本人报404，旧版本/代次409，规则或状态非法422，worker不可用503。交出时冻本地，原子持久化 bot 归属/队列后才确认；失联保持冻结并查询，不生成第二个 requestID。

reclaim 先持久化pending操作并禁止普通planner提交；非消行阶段在下个安全步暂停、epoch+1并废止旧worker租约，返回完整最新状态与player归属。若正在clearing，只允许独立transition路径按原剩余逻辑时间完成本次清行（正常≤180ms），暂停新生成的下一块再交回，不能额外执行Bot动作。过渡中崩溃仍从已提交计时恢复，查询返回pending，客户端保持冻结；不持有跨等待数据库事务。客户端同步后倒数恢复。暂停/换Bot同样先确认状态；旧worker即使仍在计算也不能提交。再次交出需携带前次返回的server version和新本地快照。clientID存储在当前安装内，服务端以登录userID鉴权，clientID仅绑定回接设备，不作为鉴权凭据。

服务端独立受监督进程 `python -m verabot.services.tetris_sessions`，不依赖手机，不占聊天/定时任务worker。默认最多16局活跃、每用户1局；租约10s、每2s续租；API仅在worker心跳10s内且有容量时接受新接管。worker每100ms最多推进100ms逻辑并原子持久化快照与事件，再发布版本；故障恢复从最后提交点重新计时，不按现实停机时间补落。逻辑步10ms，CPU规划有预算，不能阻塞其他会话。

首版前台每250ms读取最新状态，paused每2s读取，后台停止轮询；服务端驱动，客户端不得自行补走。每次读取返回≤64KiB，事件最多100条且有cursor与快照降级；同eventSequence去重，重入只展示最新进度。进行中记录保留，结束7天后清理快照/事件/幂等记录；删除账号立即按外键与服务规则清理。

规划器只读取board/current/公开next与时钟；动作间隔最低40ms。按10ms时间步搜索可达动作路径，最多2000节点/20ms墙钟预算，超预算取目前最佳合法候选或等待重力，不能改规则/瞬移。评价按字典序：避免立即顶死 → 最少新增空洞 → 最小总堆高 → 最小表面起伏 → 最多清行 → 最短动作数 → 左侧落点。规划在数据库事务外；提交每个动作前核验epoch、租约与当前状态版本，变化则丢弃重算。高速度也可能输，不能假报必胜。

## 8. 全局交付约束

iOS最低17，Intel Mac为当前构建环境；保留 Swift Package Mac 测试路径。无新第三方依赖、无全局头像重写、无 Web 改动。App工程当前为显式文件引用，新文件必须登记到 group/fileRef/BuildFile/Sources，资源登记到Resources。

构建一次一个，不擅自调整构建并发。后端测试独立脚本、临时数据库/假时钟/假模型，不调用付费模型、污染正式数据库或批量 unittest discover。跨端规则用同一份固定JSON样本，预期值人工核算，不让一个新引擎自动当另一个的唯一正确答案。

UI微调不写镜像单元测试；输入定时、碰撞、会话所有权、双写/租约和断网恢复必须有有意义的自动测试。真实声音、触感、左右手可达性与锁屏托管另行真机验收。部署前备份正式库与做独立worker监督；本轮规划不执行部署。
