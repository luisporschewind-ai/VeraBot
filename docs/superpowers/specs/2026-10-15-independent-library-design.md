# 独立资料库与 Bot 主页设计

日期：2026-10-15

状态：用户已确认产品方向；本文为待审阅的书面设计，尚未进入实现。

## 1. 目标与已确认规则

将所有 Bot 聊天中的文件、图片自动汇总为用户的独立资料库，同时扩充 Bot 页面，使用户既能全局寻找资料，也能按 Bot 浏览。资料的生命周期独立于聊天，断网后可以查看已经下载完成的内容。

用户已确认：

- 采用独立资料库；全局资料库与 Bot 文件中心展示同一份资料。
- 文件、图片分别放在独立 Tab 中展示。
- 清空对话后保留资料；只有在资料库中明确删除才移除文件本体。
- Bot 可以主动检索自己关联的资料；跨 Bot 使用须由用户明确共享。
- Wi-Fi 自动下载全部图片和文件原件；蜂窝网络仅手动下载。

这里的“原件”指服务端实际保存的文件字节。既有图片上传会进行格式处理，不能通过此次迁移恢复上传前未保存的相机原文件。

## 2. 方案选择与范围

考虑三种方式：只聚合聊天附件、给每个 Bot 单独建立文件仓库、建立账号级独立资料库并维护 Bot 关联。

采用第三种：第一种不能满足清空聊天后保留资料；第二种会让同一文件的共享、离线存储和删除变得分散。独立资料库统一管理文件本体、来源、共享关系和下载状态。

本次包含全局资料库、Bot 主页、直接上传、历史附件归集、检索授权、离线原件和兼容迁移。群聊现存附件也纳入全局资料库，以群聊标记来源；参与群聊不自动授予每个成员 Bot 长期检索权限。

此前提出的提醒、记忆等页面整体离线仍然保留为产品目标，但应另行设计和实施；不能用本次资料库交付宣称所有页面已经支持离线。

首版不包含文件夹树、文档在线编辑、版本协作、外部网盘接入、跨账号共享和离线修改队列。

## 3. 页面与交互

### 3.1 全局资料库

在首页提供“资料库”入口，首版不新增底部主导航栏目。

顶部显示标题、搜索和新增入口。内容分“文件”“图片”两个 Tab，显示各自数量。默认按最近收录时间倒序，可按来源 Bot、群聊或未关联资料筛选，并支持仅查看已下载内容。

文件采用列表：类型图标、文件名、大小、收录时间、来源和离线状态。图片采用按日期分组的三列网格；大字体与无障碍模式允许减少列数。点击图片进入全屏浏览，文件进入系统支持的预览；不支持的格式仍可查看信息及分享原件。

资料详情提供预览、分享、关联 Bot、定位来源消息和删除。搜索首版匹配文件名；有提取文本的文件同时支持正文关键字搜索，图片匹配名称及已有描述，不承诺 OCR 或语义检索。

直接上传可以选择关联一个或多个 Bot，也可以暂不关联。未关联资料只供用户查看，不对所有 Bot 默认开放。

### 3.2 Bot 主页

将当前直接打开设置表单的 Bot 详情扩展为主页，保留现有编辑表单作为右上角“编辑与权限”的入口。对话页点击标题进入主页；Bot 列表长按编辑继续直达设置。

顶部显示头像、名称、身份标签、简介及“开始对话”。下方为“概览／文件／图片”，滚动时收起大头像区域并保留分类切换。

概览展示简介和能力，并提供现有记忆、提醒、任务及协作记录入口；入口仍遵循原有权限，不在本次重做这些页面。

文件、图片使用与全局资料库相同的展示组件，固定筛选当前 Bot，不创建另一份副本。新增入口默认关联当前 Bot。“从资料库添加”明确表示授予此 Bot 检索和读取权限。

头像和资料预览不采用截图中的具体品牌形象；沿用 VeraBot 现有视觉和系统控件，检查浅色、深色、长文件名及大字体布局。

### 3.3 来源与失效状态

每项资料可有多个来源，包括私聊消息、群聊消息、直接上传。来源保留 Bot 或群名称快照和时间。

清空聊天或删除消息后，显示“原消息已清除”，禁用定位入口，资料仍可打开。删除 Bot 后保留资料和来源名称快照，移除该 Bot 的访问关联，其他关联不受影响。

缺失、未下载、下载失败、服务端已删除和文件无法预览分别显示，不能统一显示“文件已删除”。

## 4. 资料、关联与删除语义

### 4.1 独立对象

资料项由账号拥有，具有稳定 ID、类型、展示名称、MIME、大小、校验值、存储引用、收录时间、解析状态和变更版本。文件二进制及缩略图、提取文本属于资料的存储资源。

Bot 关联是独立关系，不是文件归属字段；一个资料项可关联多个 Bot。来源记录也是独立关系，不因源消息外键级联删除资料本体。

同一附件 ID 多次同步不重复创建资料。用户明确将现有资料共享给其他 Bot 时复用资料项。独立重复上传可以形成不同资料项；如按哈希复用磁盘字节，只在同一账号内进行，并通过引用计数确保删除一个资料项不误删其他资料。

### 4.2 自动归集

私聊附件成功发送后，创建或更新资料项、来源和当前 Bot 关联，与消息提交保持事务一致；回复后追加附件也使用相同路径。普通上传但尚未发送的临时附件继续遵循原 pending 过期规则，不进入资料库。

从资料库直接上传则在上传完成后创建独立资料，失败或取消留下的临时资源按现有清理规则处理。

群聊附件成功发送后建立群聊来源，但不按群成员自动扩散 Bot 关联。用户可以从资料库明确选择要授权的 Bot。

### 4.3 两个不同的删除动作

- “从当前 Bot 移除”：解除关联并撤销后续检索权限，资料继续存在于全局资料库和其他 Bot 页面。记录显式移除状态，旧消息同步和迁移不可自动恢复关联；用户主动再次共享或再次向该 Bot 发送此资料，可以重新建立关联。
- “从资料库删除”：确认框展示受影响的关联 Bot 数量，删除资料项并撤销全部关联；已有聊天中的附件卡片变为“资料已删除”，不删除消息文字。物理文件仅在无其他有效引用时回收。

清空对话不属于上述任一种资料删除。资料删除和 Bot 关联移除均留下同步标记，避免旧消息或旧设备同步后把资料重新创建。

清除本机下载仅释放该设备文件，不删除云端资料、不撤销 Bot 权限；它不是“从资料库删除”。Wi-Fi 自动下载已开启时会提示资料可能再次下载，用户可暂停自动下载以持续释放空间。

## 5. Bot 使用与授权

后端提供受当前执行身份约束的资料搜索、元数据、分段文件读取和看图能力。继续复用现有附件解析及读取实现，不将整个资料库直接塞入提示词，也不另建不受控的模型下载通道。

用户本人访问全局资料库时，验证账号所有权及资料有效状态，不要求存在 Bot 关联。Bot 执行中的每次搜索、预览、读取和下载额外验证当前 Bot 关联及已有执行工具权限；知道资料 ID 不等于获得访问权。Bot 搜索结果只能返回当前 Bot 可见的资料及片段，不泄露其他资料的标题、数量或摘要。

用户在“关联 Bot”中选择目标并确认后立即生效；取消关联后新的读取请求被拒绝，正在进行的检索或读取在返回前重新检查版本。已经发送给模型或写入历史回复的信息无法通过撤销关联追溯收回，界面不得承诺抹除既有回复。

委派其他 Bot、成为主 Bot 或加入群聊都不自动获得原 Bot 的资料权限。资料中的指令作为内容处理，不能覆盖工具权限或审批规则。

图片通过已授权的图片读取工具按需使用；正文提取失败的文件仍可保存和下载，但明确显示“暂不能检索正文”，不阻塞资料入库。

## 6. 后端与兼容迁移

当前附件表和清理逻辑与消息、Bot 生命周期耦合；服务端附件响应使用 no-store，客户端图片仅有内存缓存，Quick Look 使用临时文件。因此本次需要改变资料持久化与同步契约，不能只增加 UI 汇总。

逻辑上分为资料目录、Bot 访问关联、来源记录、存储资源和同步变更记录。实际数据库迁移版本由实现时的最新主线顺序分配，不提前占用固定版本号。服务端 SQL 集中在 `db/library_store.py`（及附件相关 `db/attachment_store.py`）；`services/library.py` 等只做规则与事务边界，不内嵌 SQL。

新增账号级分页目录、按 Bot 筛选、详情、直接上传、关联管理、搜索和删除接口；客户端不从整段聊天历史推导完整目录。返回稳定游标、目录版本和删除变更；详情返回足够的来源与权限信息供确认界面展示，并提供资源版本、准确大小和校验值供离线下载核对。面向 Bot 的工具入口必须从后端执行上下文取得 Bot 身份，不能相信模型参数传入的身份。

复用现有鉴权下载和文件解析，但持久资料不得依赖消息或 Bot 的级联删除存活。旧 attachment ID 继续可解析；聊天响应通过兼容映射取得资料状态。删除资料后旧下载入口也必须拒绝，不可留下另一条可读取原件的路径。

迁移回填现存已发送私聊及群聊附件；pending 附件不回填。依据账号、附件 ID 建立唯一映射，支持重复执行，保留原文件引用。迁移、聊天清理、启动文件对账和配额统计必须共同适配，避免对账删除仍被资料引用的文件。

既往已经物理删除的附件无法恢复，不能制造可用资料项。现存记录但文件缺失的资料保留可解释的不可用状态。历史直接上传的 pending 记录不猜测为用户已保存的资料。

迁移前备份数据库和资源引用清单；数据库升级失败不得执行后续垃圾回收。升级后的新资料不能用旧版后端管理，回退需恢复匹配的数据库和文件备份。旧版客户端可以继续聊天，但其界面不能表达独立资料库及新删除语义，不作为本功能验收客户端。

## 7. 本地持久化与离线同步

沿用现有“服务器地址 + 账号”的本地隔离和会话代号校验，在账号专属 Application Support 目录保存资料元数据、关联、来源、同步游标、下载状态及原件。凭据继续在 Keychain；退出或切换账号立即停止旧会话下载并隔离访问，迟到结果不得写入新账号目录。

所有资料页面先读本地，再异步更新。聊天附件与资料库使用同一份按账号及资源标识定位的本地文件；预览所需临时副本不作为长期存储。

登录、进入前台和用户刷新触发目录同步，完整遍历分页后才表示目录准备完成。网络失败保留上次可见数据，不把一次空响应或未完成分页当成全部资料已删除。游标失效时重新对账，完整快照与增量删除使用一致版本边界，防止恢复已删除资料。

在 Wi-Fi 下自动排队下载全部可用原件及图片预览；用户可暂停、恢复并查看“已完成／总数”、剩余体积和失败项。蜂窝网络不自动下载原件，用户可下载单项或确认批量下载并查看预计体积。网络从 Wi-Fi 切换到蜂窝时暂停尚未完成的自动传输；实现必须依靠系统网络约束控制后台下载，不能只靠开始前检查一次网络类型。

下载先写临时文件，完成后验证大小和校验值，再原子替换并标记可离线；支持失败重试和重新启动后的恢复。存储不足时暂停并明确提示，不默默删除已经完成的原件来换取“全部已下载”。

后台下载采用系统允许的调度；不承诺退出 App 后立即完成。状态以实际完成为准：目录已同步、原件下载中和全部可离线分别呈现。未下载的内容在断网时解释原因并保留条目信息。

服务端删除在下次成功同步后清理该设备原件与索引；设备断网期间仍可能保留上次已下载版本，不能承诺远程删除立即影响离线设备。Bot 模型执行依旧需要后端，离线查看不意味着离线推理。

服务端沿用现有文件类型、单文件大小和账号配额校验，资料和聊天的共享字节不重复计费；不因引入资料库悄悄扩大限额。

## 8. 验收与交付边界

验收使用独立账号及可恢复数据，不以正式账号清空聊天来做破坏性自动验证。

必须覆盖：

1. 历史私聊、群聊附件迁移及新附件自动归集，重复执行没有重复项。
2. 清空对话、单条消息删除、Bot 删除后资料保留，原消息定位正确失效。
3. 同一资料多 Bot 共享、移除单 Bot 关联、删除全局资料，以及重启和同步后的防恢复行为。
4. Bot 只能搜索和读取自己关联的资料；猜测 ID、委派、群成员身份和跨账号请求均不能扩大权限，撤销后旧下载入口也拒绝。
5. 文件解析失败、原件丢失、超额上传和部分下载失败不会破坏其他资料。
6. Wi-Fi 完整准备后，断网、退出重启再打开全局与 Bot 页面，文件与图片原件均可预览及分享；首次尚未准备的数据显示真实状态。
7. Wi-Fi 切换蜂窝暂停自动传输；蜂窝单项及批量手动下载可用；存储不足、进程退出和账号切换能正确恢复或隔离。
8. 清除本机下载和全局删除语义不同，离线旧设备重连后正确应用删除。
9. 浅色、深色、大字体、长文件名、图片网格、加载与空状态，以及返回聊天的导航行为。
10. 后端迁移、文件对账和已有聊天附件读取回归通过；现有聊天入口与快捷选项的未提交修复独立保留。

自动化验证覆盖迁移、生命周期、授权、同步与存储关键路径；模拟器及手机构建安装只证明可交付，真实断网、视觉与交互验收由用户确认。

## 9. 实施拆分与下一步

在同一产品设计下，后续实施计划依赖顺序为：后端独立生命周期与迁移、资料 API 与 Bot 授权、iOS 本地目录与下载、全局资料库与 Bot 主页、端到端验收。各阶段不能提前宣称完整资料库已可用。

本文件不修改现有产品代码，也不包含提醒、记忆等页面整体离线的实施计划。书面设计审阅通过后，再编写逐步实施计划并确认执行方式。
