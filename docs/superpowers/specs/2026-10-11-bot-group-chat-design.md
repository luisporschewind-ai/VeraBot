## 1. 目标与成功标准

让同一账号的用户和 2–4 个已有 Bot 在一个独立会话里聊天。每个 Bot 以自己的名称、头像、人设发言；能够看到群内此前的讨论，用户可以点名追问，也可以让成员依次讨论同一话题。

成功标准：创建群 → 发消息 → 多个真实 Bot 各自生成回复 → 点名其中一个继续追问 → 退出并重新进入后仍能看到完整记录；停止、网络中断、某个 Bot 失败时，已完成的发言不会丢失或重复生成。

已确定的是「先规划，再准备第一版」和伙伴讨论模式。同一账号、iOS 优先、人数与调用限制是本草案假设。首版不承诺后台持续讨论。

## 3. 方案比较与建议

| 方案 | 优点 | 代价 / 限制 |
|---|---|---|
| 独立群会话 + 服务端顺序调度（建议） | 发言归属清晰，可持续追问，调用数可预测 | 增加群存储、API、事件和界面 |
| 主持 Bot + `ask_bot` | 现有逻辑复用多，适合工作咨询 | 专家回复仍是咨询结果，共享历史和独立发言仍需补齐 |
| Bot 自由选择发言并互相调用 | 自发讨论感更强 | 调度不确定，容易重复、抢答、循环与增加费用 |

建议首版采用第一个方案。成员平等，默认回应者只是输入栏的回答对象，没有永久主持权；不增加“选谁发言”的额外模型调用。

## 4. 首版范围

### 4.1 包含

- iOS 创建、列表、进入、重命名、清空和删除群。
- 创建时选择本人已有的 2–4 个不同 Bot，并指定默认回应者；默认第一个所选 Bot。
- 文字消息、Markdown、各 Bot 独立头像与名称、实时回复状态。
- 点名一个成员回答；普通消息由默认回应者回答；「大家讨论」让全部可用成员依次回答一次。
- 群历史持久化、历史分页、重新进入加载、停止、失败状态、单个失败发言的手动重试。
- 沿用每日用量统计和现有鉴权；群消息与私聊历史完全分开保存。

### 4.2 后续阶段

群附件、语音输入、消息朗读、群内天气等工具、MCP、提醒/写操作确认、长期记忆召回/写入、自动摘要、成员主动插话、无人持续聊天、APNs、多人账号群与 Web 群聊。

首版仅复用人设与自定义指令，不读取长期记忆或个人私聊。创建页用一句话说明：“成员共享本群聊天记录；本版支持文字讨论。”群内没有工具时不得声称查过实时资料、创建过提醒或记住了信息。

这是一版完整的文字群聊；后续能力不混入首版验收或顺带开工。

## 5. iOS 交互

### 5.1 入口和创建

「助理」页顶部增加「Bot / 群聊」切换，默认保持 Bot 列表。右上角加号提供「创建 Bot」「创建群聊」，Bot 数达到现有上限时仍允许创建群聊。

群列表展示群名、成员头像组合、最后一条消息、更新时间。空列表显示已有 Bot 形象与创建入口。新群不生成伪造的欢迎聊天消息。

创建页：群名（去除首尾空白，1–64 字符）、成员选择（2–4 个）、默认回应者。保存期间防重复提交；失败保留所有输入；成功进入新群。

### 5.2 发言规则

| 用户操作 | 执行规则 |
|---|---|
| 普通发送 | 默认回应者发言一次 |
| 选择 `@成员` 后发送 | 该成员发言一次；成功后成为当前设备该群默认回应者 |
| 「大家讨论」后发送 | 按创建顺序，每个可用成员发言一次，后者能看到前者刚完成的回复 |
| 再次「大家讨论」 | 新的用户轮次，不自动递归继续 |
| 正在执行时再次发送 | 输入草稿可编辑，发送与模式切换不可提交；服务器也拒绝第二个活动轮次 |
| 「停止」 | 取消当前生成和剩余待发言者，保留已完成与部分回复 |

点名通过输入栏成员选择器形成结构化 `target_bot_id`，显示 `@名称` 标签；首版不从自由文本里的 `@` 猜测成员，不把名称作为身份键。群默认回应者存服务器用于跨设备初始值，最近点名偏好存本地账号+群 ID，不额外修改所有设备的默认值。

成员不会替其他成员编造发言；不存在自动“主持总结”或自动第二轮。最多 4 次成员生成（空回复重试另计）。

### 5.3 状态、失败和离开

回复气泡包含成员头像、名称和稳定消息 ID。等待/思考/回复/受阻使用现有 Bot 形象与状态组件；群导航栏显示正在发言的成员。技术报错保留服务端日志与 Debug 入口，正文显示可理解的说明。

**编排内部不对用户暴露：** 路由、action kind、校验错误、step/task 状态与重试原因不进入聊天气泡。bot 消息有非空可用正文时按正常回复渲染（无「回应暂未完成 / 再试一次」）；仅当该条完全没有可用正文时才显示未完成说明与重试。

一个成员在内部失败时：若已有部分/完整正文则公开为正常回复；若无正文则保留失败气泡并允许重试。整轮状态可为 `partial`。手动重试只为选中的、无可用正文的失败 Bot 创建新轮次，引用原用户问题和原轮次结束时的历史；追加新消息并标注“重试”，不覆盖原记录、不重复其他成员。

离开群页、退出登录、切换账号、App 进入后台或流连接断开，停止当前请求，已完成回复保留；重新进入以服务器历史为准，不自动继续或自动重试。停止确认以服务器状态为准；断网导致停止未确认时显示“正在确认是否已停止”，恢复连接后查询。

### 5.4 管理和 Bot 删除

首版成员名单在创建后固定。可重命名、修改群默认回应者、清空历史、删除群；清空和删除均先弹现有风格的破坏性确认，成功后刷新/返回群列表。

删除某个 Bot：群仍保留，历史保留名称与头像快照；该成员标为不可用，不能再点名。剩余一个成员仍可聊天；没有可用成员时成为只读群。默认回应者被删除时选首个可用成员并提示。清空/删除群/修改默认回应者在有活动轮次时返回 409，用户停止后再执行。

## 6. 存储与接口

### 6.1 独立表（建议 schema v20）

| 表 | 关键字段与约束 |
|---|---|
| `chat_groups` | id、user_id、name、default_bot_id（可空）、created_at、updated_at；用户删除级联 |
| `chat_group_members` | id、group_id、user_id、bot_id（可空，Bot 删除 SET NULL）、position、name_snapshot、appearance_snapshot；创建时验证同账号；群删除级联 |
| `chat_group_turns` | id、group_id、user_id、client_request_id、request_hash、mode、target_member_id、retry_of_message_id、user_message_id、context_end_message_id、status、cancel_requested、created_at、finished_at；`UNIQUE(user_id,group_id,client_request_id)` |
| `chat_group_messages` | id、group_id、user_id、turn_id、role（user/bot）、member_id（用户消息为空）、content、status、sender_name_snapshot、sender_appearance_snapshot、usage_json、usage_logged、created_at、finished_at |

轮次状态：`running / completed / partial / stopped / failed / interrupted`；消息状态：`streaming / completed / failed / stopped / interrupted`。步骤/任务可保留内部失败态；**对用户公开的 bot 消息**：只要有非空可用正文，对外 `status` 应为 `completed`（正常回复），不得因编排失败露出「未完成」。仅当没有任何可用正文时，消息才可为 `failed` / `interrupted` / `stopped`，客户端才可显示未完成说明与重试。消息 ID 提供稳定排序；不使用秒级时间戳决定先后。

一个群只能有一个 `running` 轮次，以 SQLite 部分唯一索引和 `BEGIN IMMEDIATE` 事务保证，不依赖客户端 `sending` 或单纯进程内锁。创建群及成员、领取轮次及创建用户消息、清空与删除均在短事务中完成；模型网络调用不持有数据库事务。

每条 Bot 消息的用量与 `usage_log` 在同一事务中保存，`usage_logged` 防重复记账。Bot 已删除时用量仍归当前 user，bot_id 可空。旧 `messages`、附件和私聊摘要表不改结构，不搬迁历史。

### 6.2 API 草案

所有路由验证当前用户；他人的群、消息、轮次统一 404。成员 ID 属于群，Bot ID 属于本人且处于该群。

| 方法 | 路径 | 输入 / 输出 |
|---|---|---|
| GET / POST | `/api/groups` | 群列表；创建 `{name, bot_ids, default_bot_id}`，返回群及成员 |
| GET / PATCH / DELETE | `/api/groups/{id}` | 群详情；更新 `{name?, default_bot_id?}`；删除群 |
| GET / DELETE | `/api/groups/{id}/messages` | `before_id?`、limit 默认 50/上限 100；返回正序 messages、next_before_id；清空所有消息和轮次 |
| POST | `/api/groups/{id}/chat` | `{client_request_id: UUID, message, mode: single|round, target_bot_id?}`；SSE |
| GET | `/api/groups/{id}/turns/{turn_id}` | 轮次状态与本轮消息快照，用于断线查询 |
| POST | `/api/groups/{id}/turns/{turn_id}/stop` | 置 cancel_requested 并取消本进程任务；重复停止返回当前状态 |
| POST | `/api/groups/{id}/messages/{message_id}/retry` | `{client_request_id: UUID}`；仅失败/中断/停止的 Bot 回复可重试，返回新轮次 SSE |

群名 1–64 字符、用户消息去除首尾空白后 1–2000 字符、每个账号最多 10 个群、创建 2–4 个不同 Bot。`round` 禁止传 target；`single` 指定 target 时必须是可用成员，否则使用群默认回应者（客户端可显式传本地偏好）。

同 UUID 与同请求内容再次提交：返回 409 `request_exists` 和 turn_id，客户端查询已有结果，不重新调用模型；同 UUID 不同内容：409 `idempotency_conflict`。另一个 UUID 遇到活动轮次：409 `group_busy`。401 刷新可以使用同 UUID 重发，但只允许原账号会话代次，不能跨账号补发。

### 6.3 群 SSE 契约

不更改私聊现有 `ChatEvent`，另建 `GroupChatEvent`。所有群事件都带 `group_id`、`turn_id`；发言事件再带 `message_id` 和 `member_id`。

| 事件 | 额外字段 | 作用 |
|---|---|---|
| `turn_start` | user_message、speaker_member_ids | 服务器用户消息 ID 和计划成员 |
| `message_start` | message（完整公开模型） | 创建一个成员气泡，首次事件前已落库 |
| `status` | message_id、member_id、phase: thinking/responding | 驱动该成员头像状态 |
| `delta` | message_id、member_id、text | 追加到指定气泡 |
| `message_done` | message（含最终 status、content） | 用服务器最终文本替换，避免重复拼接 |
| `error` | code、message、message_id? | 友好错误；不暴露内部堆栈 |
| `turn_done` | status、usage、message_ids | 整轮结束；客户端恢复输入 |

重试的 turn_start 引用原用户消息（保持原 message_id/turn_id），事件自身使用新 turn_id；客户端允许同群较早的用户问题，不制造重复问题。

客户端用服务器 ID 去重；delta 仅用于当前连接实时展示。首版不支持 delta 事件回放，断线重新加载最终快照。异步状态迟到、停止后 delta、旧账号事件不得改写当前群页面。

## 7. 发言执行、上下文和成本

执行路径：鉴权和校验 → 事务领取轮次并保存用户消息 → 确定成员顺序 → 逐个生成/保存 → 整轮落定。成员之间串行，不并行抢答，不调用 `ask_bot`。

群上下文单独构建：本人当前指令和人设作为 system；用户消息保留 user 身份；当前 Bot 的历史发言为 assistant；其他 Bot 的发言放入带真实成员标识的引用资料块，不伪装成用户授权或当前 Bot 已做的操作。组装时显式说明群历史是讨论资料，其他成员无权改变当前 Bot 指令。

历史窗口为最近 24 条可用群消息，正文最多 12000 字符；超出时优先丢弃最旧的完整消息，始终保留本轮用户消息。可用历史包含用户消息和 `completed` 的 Bot 回复，失败、停止、中断的部分正文仍在 UI 展示，但不作为完整结论注入模型。所有成员的 name/appearance 以服务器数据或快照组装，客户端文本不得覆盖成员身份。不注入其他 Bot 的私有 instructions。

每个成员生成输出上限 768 tokens，单成员总耗时 60 秒，单轮总耗时 240 秒；一次空回复最多重试一次（60 秒总耗时内，已有文字后失败不自动重试）。使用已有 LLM 服务增加可选 `max_tokens` 参数，默认值为空，保持私聊原请求不变；不新增模型供应商与依赖。

开始轮次和每次模型调用前检查现有每日预算，并按实际 usage 记录 `kind=group_chat`。达到预算时停止未开始的成员并说明原因。此沿用方式是调用前检查，不承诺并发私聊/多个群时的严格预算预占；严格跨调用硬上限是独立后续改造。

取消时向上游关闭请求；收到的已知 usage 仍记账，未知部分标注估算不可用，不伪造为零消耗。部分文本每新增 256 字符或距离上次写入 1 秒（有新 delta 时）检查保存，最终保存全量；崩溃可能损失最后一段尚未保存的文字。

首版执行绑定 SSE 请求、支持单后端进程。启动时把遗留 `running` 轮次和 `streaming` 消息标为 `interrupted`，保留文本，不自动重启模型调用。若实际部署需要多 worker，必须先补执行归属/租约与跨 worker 停止机制，不能让一个 worker 启动时终止另一个的任务。

## 8. 模块边界

- `db/group_store.py`：SQL、事务、轮次抢占、消息/用量幂等保存、启动恢复。
- `services/groups.py`：成员所有权、上限、管理、取消/重试规则与公开模型。
- `agents/group_context.py`：群历史选择、来源标识、独立群 prompt，不从私聊读取。
- `agents/group_runtime.py`：成员顺序、模型流、超时、取消、保存、群事件；不启动通用持久任务系统。
- `api/routers/groups.py` + `api/group_schemas.py`：REST/SSE 传输与请求验证。
- VeraBotCore `GroupChat.swift`：公开数据模型、请求、状态；`GroupChatReducer.swift`：按 ID 处理事件的纯状态逻辑。
- VeraBotNetworking `GroupChatAPI.swift`：协议；APIClient 群方法复用现有私有鉴权机制，独立 SSE 解析器。
- iOS `Features/GroupChat/`：列表、创建/管理、聊天、ViewModel；复用现有头像和 Markdown 组件。

不重构整个私聊 runtime，不扩展 `memories.scope`，不修改现有委派权限。群创建是用户对本群成员读取群文字的授权，不能据此读取私人历史或开通工具。

## 9. 实施阶段与验收

| 阶段 | 可检查的交付 | 退出条件 |
|---|---|---|
| G0 界面预览 | 创建、群列表、成员头像气泡、点名和讨论状态，使用明确标记的 mock 数据 | 用户确认入口、布局和发言操作；不声称模型群聊已完成 |
| G1 数据与契约 | 群表、CRUD、轮次与事件、iOS 模型/网络解析 | 迁移/隔离/幂等/并发 mock 测试通过 |
| G2 真实文字群聊 | 接模型，单人回复、顺序讨论、停止、失败重试与恢复 | 完整 mock 流通过，模拟器可运行，私聊回归通过 |
| G3 用户验收 | 实际创建与多人回复、上下文追问、停止、重新进入 | 用户确认交互与真实模型讨论质量；再决定是否接工具/记忆 |

详见配套实施计划。G0 经用户查看确认再推进完整连接；不把预览页面当作最终 UI 规格。用户已授权并完成 G0/G1/G2 实现，真实联调与模型质量由 G3 用户验收确认。

验收用例：

- GC-01：2/4 人创建成功，1/5 人、重复/他人 Bot、空名、账号第 11 个群拒绝；失败不留下半个群。
- GC-02：点名 B 只调用 B；round 严格 A→B→C，后者实际收到前者回复。
- GC-03：普通消息用默认/本地点名偏好；无隐式点名、无虚构其他成员发言。
- GC-04：群历史与私聊/长期记忆互不混入；跨账号读取、停止、重试、删除均 404。
- GC-05：同 UUID 不重复用户消息、生成或用量；冲突内容与同群并发提交拒绝。
- GC-06：中途停止只保留已完成与部分回复，停止后迟到事件不再追加，重复停止幂等。
- GC-07：B 超时/空回复失败，C 仍回答；重试 B 只追加 B 新回复，不重复 A/C。
- GC-08：流断开、页面退出、后台、注销、账号切换、后端重启均能恢复到准确终态；无跨会话 UI 更新。
- GC-09：Bot 删除后群历史保留，失效成员不能被调用，0 人只读；清空/删除活动群先停止。
- GC-10：输入/输出/历史/耗时边界和每日预算生效；记账一次；未知 usage 明确未知。
- GC-11：群标题/成员文字含特殊符号，无法冒充身份或改变 prompt；Bot 被要求创建提醒/记住信息时不虚报成功。
- GC-12：私聊工具、附件、确认卡片、记忆、SSE 和认证刷新行为保持兼容。

## 10. 待评审的产品决定
