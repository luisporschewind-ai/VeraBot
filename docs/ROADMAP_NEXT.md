# 后续工程规划 (Beyond v0.1)

状态：规划草案；不代表已批准实现或排期。依据 `docs/STATUS.md` §4 第 3–11 项整理。MCP / Gmail、Bot 置顶、iOS 验收和记忆 M2 按各自状态跟踪。

## 建议顺序

### 0. 发布与质量底座

- 建立 CI：后端 mock 测试、VeraBotKit `swift test`、iOS Simulator `xcodebuild`。
- 验收：干净 macOS runner 可重复构建；CI 不触发 UI 自动化或真实模型调用；失败能定位到具体 job。
- 前置：确认 GitHub Actions runner 与 macOS 构建额度 / 成本。

### 1. 安全与本机部署边界

- Token 存储从 UserDefaults / localStorage 迁移到 iOS Keychain 与 Web HttpOnly Cookie；配套登录、登出、失效和迁移策略。
- 加入登录、写接口和高成本模型调用的速率限制；覆盖多 worker 部署下的共享限流存储。
- 明确开发局域网 HTTP 与生产 HTTPS 配置，收紧生产 CORS；iOS ATS 例外仅保留在开发配置。
- Docker：启动可重复的数据库卷、环境变量和健康检查；构建并实际运行镜像后记录结果。
- macOS 后端常驻：在 Docker 方案与 launchd 之间先选定唯一主要部署方式；若面向本机用户，launchd 支持崩溃重启和日志轮转。
- 验收：登录态不泄漏；跨用户隔离回归通过；限流返回稳定错误；生产配置拒绝明文与宽 CORS；重启后数据保留。

### 2. 提醒通知

- 优先评估本地通知 (`UNUserNotificationCenter`)：现有提醒只落库，确定提醒时间、时区、编辑/删除、权限拒绝和重启重排规则。
- APNs 作为多设备/服务端触达的独立后续决策，不与本地通知捆绑。
- 验收：授权、拒绝、时区变化、重复启动、提醒完成/删除和通知点击路径均有手测用例。

### 3. 图片附件与多模态

- 先确定支持图片的模型、上传大小/格式上限、压缩方式、服务端保留期和隐私删除策略。
- 后端建立有用户隔离的上传/引用协议；对话请求传递附件引用，并将图片发送给支持视觉的模型；UI 再接入相册、相机和附件预览。
- 验收：格式与大小错误可解释；用户不能读取他人附件；删除对话/附件按保留策略清理；视觉请求有成本上限。

### 4. 云端 TTS

- 选定供应商、语音、语言、超时/缓存策略、费用预算和密钥配置；实现 `/api/tts` 与 iOS `CloudTTSEngine`，本机 TTS 保留为回退。
- 验收：网络失败回退、取消播放、语言与音色可用、音频不被误记入对话正文、额度与隐私行为可说明。

### 5. Web 客户端方向决策

- 在实现 Web UI 前决定是否继续维护 Web：若继续，先列出必须追平的权限编辑、协作记录、设置/TTS、记忆确认、头像/标签/置顶等能力；若仅用于 API 验收，则维持冻结并避免复制 iOS 交互。
- 验收：明确维护责任、支持矩阵和最低安全标准后才开实现任务。

## 开始下一阶段前的决策

1. 确认目标用户和部署形态 (仅本机 / 局域网 / 公网)，据此排序安全、Docker 与 launchd。
2. 确认 CI 的 macOS runner 成本与可用性。
3. 确认提醒先做本地通知，以及 Web 是否继续维护。
4. 确认图片与云端 TTS 的模型/供应商、预算和数据保留策略。

除 CI 与安全底座外，其余功能不应因列入此规划而自动开工；每项仍需单独规格、验收条件和状态更新。
