# Bot 动态开场词（Opening Message）— Phase 1

状态：Phase 1 实现中（iOS + 后端）。`frontend/web` 冻结，不改。  
范围：仅改空对话时**已有开场气泡的文案内容**；不改 UI 布局、输入栏或气泡样式。

## 目标

空对话里那句硬编码开场（曾含「石家庄天气怎么样」等功能清单）改为**随时间、日期、人设、轻量用户信息与关系阶段变化**的问候；风格关心人、有个性、通用，**不罗列功能、不硬编码城市**。

示例（大管家 · 周五晚上）：

> 周五晚上好，Boss。这周辛苦了，周末有什么想安排的，交给我。

## 维度

| # | 维度 | Phase | 说明 |
|---|---|---|---|
| 1 | 时段 | 1 | 早上 / 中午 / 下午 / 晚上 / 深夜；深夜追加关心句「早点休息」 |
| 2 | 日子 | 1 | 周一、周五、周末；中国法定节假日；二十四节气（如「霜降了，早晚添件衣服」） |
| 3 | Bot 角色 | 1 | 语气与邀请随名称/人设：健康助手偏健康关心；调查员「想查点什么」；大管家「有事交给我」 |
| 4 | 对用户的了解 | 1 | 轻触「Vera 了解的你」：优先称呼偏好；最多一个小细节，不碰敏感信息 |
| 5 | 关系阶段 | 1 | 初识：短自我介绍；之后再进空对话：问候 + 延续感，不重复自我介绍 |
| 6 | 天气/季节 | **2（不做）** | 基于定位 + 天气 API；本 PR 不实现 |

### 时段划分（本地时区，默认 Asia/Shanghai 语义由客户端日历决定）

| 时段 | 本地小时 `[start, end)` |
|---|---|
| 深夜 | 23–5 |
| 早上 | 5–11 |
| 中午 | 11–13 |
| 下午 | 13–18 |
| 晚上 | 18–23 |

### 日子优先级（同一天只取最强一条「日子提示」）

1. 中国法定节假日（元旦、春节、清明、劳动节、端午、中秋、国庆等；用固定公历表 + 近年农历节日表）
2. 二十四节气当日（如霜降）
3. 周一 / 周五 / 周末
4. 普通工作日：无额外日子提示，只保留时段问候

### 关系阶段

- **初识（first_meeting）**：当前私聊会话世代 `conversation_generation == 1` 且消息列表为空 → 短自我介绍 + 人设邀请。
- **再遇空对话（returning）**：`conversation_generation > 1`（例如清空对话后）→ 问候 + 延续，**不再**自我介绍。

边界：逐条删光消息但未走「清空对话」时世代仍为 1，可能仍走初识文案；接受为 Phase 1 近似，记入 known-issues。

### 对用户的了解（轻量）

- 优先：生效记忆里可解析的称呼偏好（如「称呼用户为 Boss」）。
- 否则：账号昵称 / 展示名。
- 都没有：省略称呼占位，不捏造。
- **禁止**：健康、财务、精确住址、他人隐私等敏感细节进入开场词。

## 生成架构（混合）

```
创建 Bot（及存量懒生成）
        │
        ▼
  后端 DeepSeek 一次调用
  → 生成少量「人设风格模板」（含占位符）
  → 存 bots.opening_templates（JSON）
        │
        ▼
  打开空对话（iOS）
  → 本地用模板 + 时段/日子/关系阶段/称呼组装
  → **不调用模型**
  → 模板缺失或生成失败 → 内置通用模板兜底
```

### 模板约定

JSON 形状（版本字段便于演进）：

```json
{
  "version": 1,
  "first_meeting": [
    "{greeting}，我是{bot_name}。{invite}"
  ],
  "returning": [
    "{greeting}，{address}。{day_note}{invite}"
  ],
  "invite": "有事交给我。"
}
```

占位符（客户端填充）：

| 占位符 | 含义 |
|---|---|
| `{greeting}` | 组合问候，如「周五晚上好」「霜降早上好」 |
| `{address}` | 称呼；空则客户端去掉多余逗号/空格 |
| `{day_note}` | 日子/节气关心句；无则空 |
| `{bot_name}` | Bot 名称 |
| `{invite}` | 人设邀请句（亦可写死在单条模板里） |
| `{late_care}` | 深夜关心；非深夜为空 |

模型生成约束：关怀、通用、有个性；禁止功能清单与具体城市名；模板条数约 2～4 条/阶段，便于客户端轮换。

### 后端行为

1. **创建时**：插入 Bot 后异步（或请求后后台任务）调用 DeepSeek 一次生成模板并写入；失败不阻断创建，列保持 `NULL`。
2. **懒生成**：`POST /api/bots/{id}/opening-templates/ensure` — 若已有模板则原样返回；否则尝试生成；失败返回 `opening_templates: null`，客户端用兜底。
3. **公开字段**：`public_bot` 增加 `opening_templates`（对象或 `null`）。可选同响应附带 `opening_address`（由记忆轻量解析的称呼，可空）。
4. **人设/名称 PATCH**：清空 `opening_templates`，下次 ensure / 打开时懒生成。
5. **SQL**：仅经 `db/`；新迁移 `v032_opening_templates`。

### iOS 行为

1. 空对话且历史完整时，用 `OpeningMessageComposer`（VeraBotCore）组装文案，替换原硬编码字符串。
2. 若 `bot.openingTemplates == nil`，立即用内置兜底展示，并后台调用 `ensure`（成功则刷新 Bot 缓存，不影响本次文案亦可）。
3. **不改**气泡布局、Markdown 渲染方式以外的 UI；开场仍是一条本地 `Item`（无 `messageID`），不写服务端消息表。
4. `frontend/web` 不动。

## 兜底文案（内置）

初识示例：`{greeting}，我是 **{bot_name}**。{invite}`  
再遇示例：`{greeting}{address_clause}。{day_note}{invite}`  
默认 `invite` 按名称启发（含「健康」→健康关心；「调查」→想查点什么；「管家」→有事交给我；否则「有什么想聊的，跟我说。」）。

## 非目标（Phase 1）

- 天气 / 定位 / 季节 API（维度 6）
- Web 客户端
- 开场词写入服务器消息历史或改变未读逻辑
- UI 改版、快捷提问条替换开场词

## 测试

**后端**：模板生成（mock DeepSeek）、校验/落库、ensure 幂等、创建后字段、PATCH 人设清空、称呼解析不泄敏感。  
**iOS（VeraBotCore）**：时段、周一/周五/周末、节假日、节气、关系阶段、占位符清理、兜底路径。  
本 Linux 云环境无 Swift 工具链：Swift 测试以源码交付，在 Mac 上 `swift test`；后端离线脚本可在本环境跑。
